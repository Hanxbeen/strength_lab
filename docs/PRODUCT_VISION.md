# 제품 비전 — 훈련·회복·영양을 연결하는 개인 스포츠과학 서비스

상태: 2026-10-18 사용자 방향을 반영한 장기 전략. 현재 구현·효과 검증 완료를 뜻하지 않는다.
현재 MVP: 무게무게. SBD 중량 향상이 첫 검증 대상이다.

## 지향점
엘리트 선수를 지원하는 스포츠과학 팀의 의사결정 과정 중 근거로 설명하고 재현할 수 있는 부분을 일반인의 시간·비용·장비·생활 조건에 맞게 제공한다. 훈련 계획, 실제 수행, 회복·영양 맥락, 다음 선택, 기간별 결과를 연결해 사용자가 자신의 목표에 맞는 결정을 지속하도록 돕는다.

최고 선수와 같은 성과·의료 지원·실험 정확도를 보장한다는 의미는 아니다. 특정 선수의 지출이나 관리 방식은 검증된 사실로 사용하지 않는다. 차별점은 유명 선수 사례나 수집한 논문 수가 아니라, 어떤 근거와 개인 기록이 다음 선택에 반영됐는지 설명하고 결과를 다시 검토할 수 있는 체계다.

## 무게무게가 증명할 것
1. 자신의 경험과 환경에 맞는 루틴을 실제로 선택·시작할 수 있다.
2. 계획과 달리 운동해도 중량·반복·휴식·미완료·중단이 정확하게 남는다.
3. 기록이 다음 선택에 어떻게 쓰였는지 이해할 수 있다.
4. 입력 부담을 감수할 만큼 기록·안내가 유용해 반복 사용한다.
5. 비교 가능한 기간별 측정으로 수행 변화를 관찰할 수 있다. 관찰된 성장만으로 앱의 인과적 효과를 주장하지 않는다.

현재 우선순위는 숙련도별 실제 루틴 데이터, 전체 운동 흐름, 저장·복구·인증 연결이다. 회복·식단·제품 추천·새 브랜드는 이를 막는 선행 작업으로 만들지 않는다.

## 단계별 확장과 진입 조건
| 단계 | 제공 범위 | 다음 단계로 넘어갈 증거 |
| --- | --- | --- |
| 1. SBD MVP | 루틴 선택·입력·실행·휴식·변경·중단·완료·다음 회차 | 숙련도별 실사용 데이터, 실제 계정 종단 실행, 기록 보존과 사용자 이해 확인 |
| 2. SBD 회복 관찰 | 수면·피로·근육통·생활 맥락의 최소 체크인과 개인 내 추세 | 입력 지속성·누락률·부담, 수행 기록과 시간적 연결의 유용성 검증 |
| 3. 회복·영양 의사결정 지원 | 근거와 적용 조건을 갖춘 설명·선택지, 검토된 범위의 일정/부하 조정 | 단순 기록 대비 의사결정 개선과 잘못된 안내·과도한 제한 여부 검증 |
| 4. 인접 목표 | 근비대·일반 근력·체간 기능 등 목표별 모듈 | 각 목표의 수요·평가 지표·근거·운동 경로 검증. SBD 효과의 자동 전용 금지 |
| 5. 종목 확장 | 격투기·달리기/마라톤 등, 복합 목표와 일정 충돌 관리 | 종목별 전문 검토·기록 단위·부하/회복 규칙·사용성 검증 |
| 6. 통합 서비스 | 훈련·회복·식단·선택적 제품 추천 | 교차 모듈의 유용성, 신뢰·개인정보·이해상충 관리가 유지됨 |

달력 날짜나 기능 개수만으로 다음 단계를 열지 않는다. 각 단계에서 범위를 줄이거나 보류할 수 있다. '코어 성장'은 모호하므로 체간 근력·지구력·기능 등 실제 평가할 목표로 구체화한 뒤 채택한다.

## 회복 모듈의 방향
회복은 핵심 축이지만 '성장의 유일하거나 항상 가장 중요한 원인'으로 확정하지 않는다. '빈도가 높으면 나쁘다'는 고정 규칙도 두지 않는다. 훈련량·강도·분배·일정·생활 맥락과 실제 반응을 함께 검토한다. 근육이 회복됐다는 생리적 상태를 단일 자기보고 점수로 확정하지 않는다.

기록→개인 내 추세→맥락 확인→근거 있는 선택지→선택과 결과 추적 순으로 확장한다. 처음부터 하나의 회복 점수나 자동 감량 계수를 만들지 않는다.

| 영역 | 후보 입력 | 사용 목적과 한계 |
| --- | --- | --- |
| 수면 | 수면 시간, 주관적 질1–10, 필요할 때 중도 각성 | 본인 추세와 운동 맥락. 1–10은 초기 UX 후보이며 검증된 척도라고 부르지 않음 |
| 피로·근육통 | 주관적 피로, 부위별 뻐근함, 통증 별도 | 수행 변화의 맥락. 통증을 근육통 또는 근력 부족으로 합치지 않음 |
| 식사 | 섭취 규칙성, 목표 관련 섭취 여부, 필요할 때 상세 기록 | 영양 목표에 필요한 항목만. 음식의 질을 단일 선악 점수로 평가하지 않음 |
| 소화 | 불편 여부, 시점, 운동/식사와의 관계 | 자기보고 관찰. 음식 불내성·흡수율·질환을 앱이 진단하지 않음 |
| 생활 | 스트레스·질병·음주·출장 등 선택적 맥락 | 설명/선택에 실제로 사용되는 항목만 수집 |
| 일정 | 계획/실제 운동 간격, 세트 간 휴식, 다른 활동 | 세트 사이 휴식과 세션 사이 회복을 구분. 다른 종목 부하도 장기적으로 연결 |

체크인은 매일 모든 항목을 강요하지 않는다. 최소 질문을 먼저 시험하고 세부 질문은 상황에 따라 연다. 수면 질1은 매우 나쁨,10은 매우 좋음 같은 문항·끝점·회상 기간을 고정해 버전 관리한다. 점수 변경·누락·모름을 구분하고 누락을 정상이나0점으로 대체하지 않는다. 서로 다른 척도나 웨어러블 추정치를 같은 측정으로 합치지 않는다.

## 향후 데이터 계약
구현 전 문항마다 사용할 판단과 근거를 정한다. 논문에 등장했다는 이유만으로 모든 변수를 수집하지 않는다.
- observation: 사용자/시점/현지 날짜·시간대/회상 구간/문항 버전/값·단위·척도/출처(자기보고·기기)/누락 사유/정정 이력.
- linkage: programme/version/session 및 관련 평가 기간. 훈련 전후 시점을 구분하고 미래 정보를 과거 처방 근거로 소급 사용하지 않는다.
- decision: 입력 스냅샷, 근거·규칙 버전, 적용/비적용 이유, 불확실성, 제안, 사용자 선택, 실제 실행을 보존한다.
- outcome: 수행·지속성·주관적 유용성·목표별 측정. 상관관계와 인과관계를 구분하고 선택 편향·중도 이탈을 함께 본다.
- governance: 선택 동의, 수집 최소화, 접근 통제, 내보내기·삭제·보유 기간, 외부 기기 연결 철회. 건강 관련 기록을 광고 추천에 무단 전용하지 않는다.
이는 후속 설계 계약이며 현재 회복 DB/API가 존재한다는 의미가 아니다. 지금 범용 플랫폼을 미리 구현하지 않는다.

## 영양·제품 추천 원칙
식단은 목표·선호·예산·알레르기 등 적용 조건을 확인하고, 임상 영양 문제가 있는 경우 전문 지원 영역을 구분한다. 개인 칼로리·영양소 처방 수치는 후속 근거 검토로 결정한다.
제품 추천은 문제와 필요성부터 확인한다. 구매 불필요·일반 식품·비구매 대안을 함께 고려하며 추천 근거, 한계, 비용, 광고/제휴 관계를 표시한다. 수익률이 회복 판정이나 추천 순위를 몰래 바꾸지 않도록 분리한다. 보충제 사용이나 구매를 성장의 필수 조건으로 만들지 않는다. 종목별 금지성분·품질 문제는 해당 기능 도입 시 별도 검토한다.

## 브랜드와 사업 가설
무게무게는 파워리프팅 문제와 사용자 수요를 검증하는 MVP 브랜드다. 종목을 넓힐 실사용 증거가 생기면 상위 브랜드+무게무게 모듈 또는 통합 리브랜딩을 비교한다. 지금 이름·로고·디자인 토큰을 변경하지 않는다. 릴라와 쌓인 기록의 연속성은 후속 의사결정에서 검토한다.
수익화는 기록의 정확성과 근거 접근을 해치지 않는 코칭 가치에서 검증한다. AI는 설명·검토를 도울 수 있지만 입력/근거/규칙/책임 범위를 대신하지 않는다. 다종목 확장은 사업 가설이며 SBD MVP 성공만으로 다른 시장의 수요가 입증되지는 않는다.

## 적대적 검토와 중단 기준
- 슈퍼앱 범위가 현재 루틴 출시를 늦추면 확장을 보류한다.
- 체크인 부담이 가치보다 크면 항목을 줄인다. 단순히 데이터가 많다는 이유로 유지하지 않는다.
- 수면 점수와 수행의 동행을 원인으로 표현하거나 보편 감량 계수로 바꾸지 않는다.
- 안내가 과도하게 운동을 제한하거나 통증을 무시하게 만들면 해당 규칙을 중지·수정한다.
- 제품 판매와 과학적 권고가 충돌하면 권고 독립성을 우선한다.
- 모듈 간 충돌을 해결할 근거가 없으면 불확실성을 제시하고 자동 조정을 하지 않는다.
