# 무게무게 구현 현황 — 2026-10-11

## 이번 정정

이전 BrandUI 단독 확장은 공유 토큰·플랫폼별 네이티브 파운데이션을 충분히 구현하지 못했다.
공유 JSON과 SwiftUI 생성기로 수정했으며, 최신 승인 시안의 출처·텍스트 대비 보정값을 DESIGN_SYSTEM.md에 명시했다.
별도로 확정된 외부 Solid 라이브러리나 토큰 원본이 있었다는 근거는 찾지 못했다.

## 구현 및 확인

- 공유 토큰: design-tokens/tokens.json → scripts/generate_design_tokens.py → MugeStyle. 라이트/다크 색상·간격·반경·타이포·크기와 일치 검사.
- 3탭, 첫 사용 안내, 최대 중량 단계 입력·일괄 저장, kg/lb 표시, 체험 루틴 분리, 실측·추정 차트는 1차 구현을 유지.
- 연구 배치 재실행: 요청 20편 중 XML 확보 3편, 검토 대기 3, 공개 프로토콜/차트 각각 0.
- 실제 Supabase에 배치·논문·검토 후보·해시·근거·차단 사유 저장. 중복 적재와 공개/비공개 접근 검증.
- 앱과 FastAPI가 실제 DB RPC를 조회. 빈 배열 하드코딩 제거, DB 오류와 공개 데이터 없음 상태 분리.
- 앱 빈 상태에는 DB의 후보·검토 대기 수 표시. 후보를 실행 가능한 처방으로 제공하지 않음.
- Python 65개 테스트, Swift 14개 테스트, Swift 및 Python 실제 RPC 조회, Xcode Debug 빌드 통과.
- 수정 앱 Hanbeen iPhone 설치 완료. 최신 수정본 자동 실행은 기기가 잠겨 실패. 앞선 1차 구현본은 설치·실행 모두 확인.
- 수동 화면 검수·VoiceOver·모든 Dynamic Type 통과는 주장하지 않음. Mac에 시뮬레이터 런타임이 없었음.
- GitHub 이전 create-tree 요청 403. 이후 read API에는 사용자 push 권한이 표시됐지만 도구의 쓰기 범위 해결은 미확인. 원격 쓰기는 재시도하지 않음.

## 남은 원래 명세

1. 운동 schema v2, 변환 전 백업·참조 검사·클라우드/백업 버전 호환.
2. 불변 계획 스냅샷, 세트 건너뛰기·수정 이력, 남은 세트 적용과 선택적 이유.
3. 실제 RestInterval 이력, 휴식 횟수·경과·연장/일시정지 이벤트·복구 확인.
4. 결과의 계획 대비 중량/횟수/휴식 차트와 수행량 분석.
5. 추정 StrengthRecord 저장·근거 정보와 회수 버전의 운동 재개 정책.
6. 독립 사람 검수 및 승인된 연구 루틴 확보. 목표 수를 맞추기 위한 자동 승인 없음.
7. 릴라 앱 아이콘 양옆 프레이밍, 가로 눈금 입력 UX, 전체 40개 상태 실기기 검수.
