# 무게무게 서비스 원칙

버전: 0.2 · 후속 명세와 적대적 재검토를 반영한 설계안  
기준 대화: 2026-10-11~12, Asia/Seoul  
문서 성격: 서비스가 지향할 가치와 판단 기준. 현재 구현 완료나 과학적 효과 검증을 선언하는 문서가 아니다.

## 1. 서비스의 목적

무게무게는 스쿼트·벤치프레스·데드리프트의 중량 향상을 목표로 하는 사용자가 연구 근거에 기반한 훈련을 선택하고, 자신의 수행 기록을 활용해 다음 훈련을 결정하도록 돕는 코칭 서비스다.

사용자가 논문이나 훈련 이론을 잘 알지 못해도 시작할 수 있어야 한다. 사용자의 출발 조건에 맞춰 오늘 수행할 내용을 보여주고, 수행이 달라졌을 때 기록·설명·다음 선택으로 연결한다.

핵심 경험은 다음과 같다.

**내 조건으로 훈련을 시작한다 → 실제 수행과 변경을 남긴다 → 목표와 변화를 확인한다 → 이전 경험과 근거를 다음 선택에 활용한다.**

근비대, 보조 운동, 휴식·회복, 피로 관리, 장기 진행과 기록 측정은 파워리프팅 목표와의 관련성을 설명할 수 있는 범위에서 다룬다. 대회 출전은 서비스 이용의 필수 조건이 아니다.

## 2. 원칙 P01 — 사용자의 훈련 판단을 기준으로 근거를 축적한다

연구 수집은 시작 중량, 강도·볼륨·빈도, 수행 중 조정, 보조 운동, 회복, 정체, 평가 등 사용자에게 필요한 질문에서 출발한다.

논문 수, 루틴 수, 생성한 세트 수를 근거의 충분성으로 간주하지 않는다. 각 질문에 대해 답할 수 있는 범위, 불확실한 범위, 아직 답할 수 없는 범위를 관리한다. 검색하기 쉬운 논문만으로 추천 범위를 결정하지 않는다.

파워리프팅 수행을 직접 다룬 근거와 일반 근력·근비대·회복 연구에서 간접 적용한 근거를 구분한다. 효과가 없거나 상반된 결과도 검토 대상에 포함한다.

## 3. 원칙 P02 — 연구의 조건과 한계를 함께 전달한다

실험군을 추출했다는 이유만으로 추천 프로그램으로 채택하지 않는다. 대상자, 비교군, 전체 훈련 구성, 진행·조정 규칙, 측정 방식, 결과와 불확실성, 탈락·수행률, 통제 조건을 검토한다.

미보고 항목은 미보고로 남긴다. 연구가 검증한 범위보다 넓은 효과·적용 범위를 주장하지 않는다. 각 수치와 판단은 원문 위치 또는 명시된 운영 규칙으로 추적할 수 있어야 한다.

초기 화면은 사용에 필요한 요약을 제공하고, 상세 화면에서 연구 조건·한계·원문을 확인할 수 있게 한다. 연구 정보를 보존하기 위해 사용자에게 논문 전체를 읽도록 요구하지 않는다.

## 4. 원칙 P03 — 처방과 변경의 출처를 구분한다

다음 구분을 데이터와 사용자 설명에 유지한다.

| 구분 | 의미 |
|---|---|
| 연구에서 직접 사용한 조건 | 특정 연구의 특정 실험군에서 실제 시행한 내용 |
| 여러 연구를 종합한 판단 | 여러 결과를 검토해 정리한 적용 원칙. 조합 전체가 실험됐다는 뜻은 아님 |
| 무게무게 운영 규칙 | 연구의 공백 또는 서비스 운영을 위해 정한 판단. 논문 사실로 표시하지 않음 |
| 사용자 직접 변경 | 사용자가 선택한 중량·횟수·휴식·일정 등의 변경 |

프로그램 전체의 강도·볼륨·빈도·회복 구성이 일관되는지 검토한다. 개별 요소에 근거가 있다는 이유만으로 조합 전체의 효과가 입증됐다고 표현하지 않는다.

‘운영 규칙’이라는 표시는 검토 의무의 예외가 아니다. 훈련 부하나 적용 범위를 바꾸는 제품 규칙도 적용 조건·한계·fallback과 검토 기록이 필요하다. 입력 해결, 실행기 호환, 근거 검토, 실제 공개 상태를 구분한다.

## 5. 원칙 P04 — 연구 조건, 개인 목표, 실제 수행을 분리해 보존한다

원 연구의 조건, 당시 사용자 기록으로 계산한 목표, 실제 수행한 결과를 각각 보존한다.

1RM의 측정·추정 여부, 측정 시점과 동작을 구분한다. 사용자가 1RM이나 단위를 변경해도 과거 운동의 기준과 기록을 다시 쓰지 않는다. 장비 단위에 따른 반올림도 원래 계산값과 구분한다.

세트별 중량·횟수·휴식과 변경 사유를 남기고, 실패·건너뜀·미시도·미기록을 구분한다. 평균값으로 세트별 차이나 누락을 지우지 않는다. 수정은 정정 이력을 통해 설명 가능하게 한다.

이력 보존은 개인정보를 영구 보유한다는 의미가 아니다. 삭제·철회·보유 기간 만료에 따른 개인 데이터 처리를 지원하면서, 비개인 연구·규칙 버전의 재현성과 구분한다.

## 6. 원칙 P05 — 기록이 다음 선택에 어떻게 쓰이는지 설명한다

개인화는 이전 기록을 바탕으로 다음 훈련의 선택이나 안내를 달리하는 것이다. 어떤 기록을 어떤 조건과 규칙으로 반영했는지 확인할 수 있어야 한다.

동작, 반복수·세트 구성, 휴식, 목표 노력도, 수행 시점 등 비교에 필요한 조건을 검토한다. 비교가 어려운 기록을 자동 환산에 사용하지 않는다. 세부 비교 기준과 반영 범위는 후속 명세에서 근거와 함께 정한다.

원 연구가 제시한 조정, 다른 근거를 적용한 조정, 제품 규칙, 사용자 선택을 구분한다. 자동 조정은 적용 조건과 범위가 명세·검토된 경우에 제공한다. 근거가 부족하면 과거 수행 정보와 선택지를 제공하거나 필요한 정보를 확인한다.

사용자는 조정 이유를 확인하고 선택을 바꿀 수 있다. 개인화 결과는 처방·변경·수행·결과가 연결된 이력으로 남긴다.

단순 기록 설명, 과거 참고, 조정 제안, 자동 반영의 제공 범위를 나눈다. 근거가 없는 자동 처방을 제한하더라도 가능한 기록·과거 참고·사용자 선택은 유지한다. 사용자 동의가 적용 근거의 부족을 해소하는 것으로 처리하지 않는다.

## 7. 원칙 P06 — 수행 달성과 성장 효과를 구분한다

목표 중량·반복수·휴식과 실제 수행의 차이는 기록 비교다. 그 비율을 성장률, 효과 달성률 또는 정체의 원인으로 바꿔 표현하지 않는다.

한 번의 운동 종료에서는 수행 차이를, 전체 프로그램 종료에서는 기간별 수행 변화와 평가 결과를 제공한다. 측정 조건이 다른 기록은 차이를 명시하고, 추정 1RM과 실제 측정 1RM을 구분한다.

연구 집단의 평균을 개인의 예상 성장이나 합격선으로 사용하지 않는다. 연구에서 측정하지 않은 주차별 성장 곡선을 생성하지 않는다. 관찰된 변화와 그 원인에 대한 해석을 분리한다.

## 8. 원칙 P07 — 현실적인 변경을 지원하고 판단의 공백을 숨기지 않는다

목표 미달, 중량 조절, 휴식 변경, 일정 변경, 중단 등이 발생했을 때 사용자가 실제 수행을 남길 수 있어야 한다. 지원하지 않는 변경은 그 한계와 가능한 다음 행동을 설명한다.

계획과 다르게 수행한 기록을 실패한 사용자에 대한 평가로 표현하지 않는다. 변경이 원 연구 조건에서 얼마나 벗어났는지와 해석의 한계를 알린다.

연구나 기록으로 원인을 확인할 수 없다면 확인할 수 없다고 말한다. 통증 등 수행 저하와 구분해야 할 상황을 단순한 중량 조절 문제로 단정하지 않는다. 무게무게의 코칭이 모든 상황을 해결하거나 개인 효과를 보장한다고 약속하지 않는다.

## 9. 원칙 P08 — 필요한 정보만 묻고, 오늘의 행동은 간단하게 보여준다

질문은 답변을 어떤 판단에 사용할지 정해져 있어야 한다. 모든 논문의 모든 변수를 매일 입력하도록 요구하지 않는다.

초기 설정, 운동 전 확인, 세트 기록, 문제 발생 시 추가 확인을 구분한다. 이미 기록에서 확인할 수 있는 정보는 반복해서 묻지 않는다. 누락이나 응답 불확실성도 표현한다.

주요 화면은 다음 행동을 쉽게 알 수 있게 하고, 설명과 근거는 필요할 때 펼쳐 볼 수 있게 한다. 질문 수, 문구, 기록 단계는 실제 사용성을 검증하며 정한다.

## 10. 원칙 P09 — 연구 업데이트와 운영 처방 변경을 분리한다

초기에는 코칭 질문을 충분히 다루는 근거 체계를 구축한다. 이후 주 1회 신규 연구·정정·철회 확인을 목표 운영 주기로 두되, 실제 가동 여부는 별도로 관리한다.

자동화와 AI는 발견·분류·추출·비교·영향 분석·알림을 보조한다. 그 출력 자체를 과학적 검토 완료로 간주하지 않는다. 운영 규칙이나 루틴의 채택·변경은 근거와 영향 범위를 검토한 뒤 버전으로 배포한다.

일반 업데이트는 진행 중인 프로그램을 조용히 덮어쓰지 않는다. 철회나 중대한 문제가 확인되면 별도 대응 기준에 따라 알림·추천 중단·재선택을 처리하고, 과거 실행 이력은 보존한다.

## 11. 원칙 P10 — 사용자 사례를 별도의 관찰 근거로 축적한다

사용자 사례에는 출발 조건, 프로그램 버전, 실제 수행, 변경과 평가 조건이 연결돼야 한다. 유사 사례 탐색과 추천의 효과 주장은 구분한다.

성공 사례뿐 아니라 변화가 없었던 경우, 중도 이탈, 기록 부족을 함께 고려한다. 유사한 사용자의 결과를 해당 사용자에게 보장하지 않는다. 관찰 자료를 인과관계가 입증된 연구로 표시하지 않는다.

공유는 사용자가 공개 여부와 항목을 선택할 수 있게 한다. 공유 동의와 추천·분석을 위한 데이터 사용 범위를 구분하고, 관련 선택·철회·삭제 방식은 데이터 명세에서 정한다.

## 12. 제품 판단의 기준

새 기능·규칙·루틴을 검토할 때 다음 다섯 질문에 답한다.

1. 사용자의 파워리프팅 목표에서 어떤 판단이나 행동을 돕는가?
2. 어느 근거와 적용 조건에 의존하며 무엇이 불확실한가?
3. 어떤 사용자 정보·기록을 사용하며 입력 부담은 필요한 수준인가?
4. 목표와 실제 수행이 다를 때 무엇을 기록하고 어떻게 다음 선택으로 연결하는가?
5. 유용성을 무엇으로 검증하며, 어떤 결과이면 수정하거나 제공을 중단하는가?

루틴 수나 테스트 통과만으로 제품 가치를 입증했다고 판단하지 않는다. 기록 정확성, 설명 이해도, 사용 부담, 훈련 지속과 선택의 유용성, 비교 가능한 수행 변화 등을 구분해 평가한다. 구체 지표와 목표값은 별도 검증 명세에서 정한다.

## 13. 이 초안에서 확정하지 않는 사항

필요 논문 수, 초기 지원 사용자 범위, 루틴별 처방 수치, 정체 판정 기간, 과거 기록 반영 기간·가중치, 유사 사용자 기준, 자동 조정 폭, 보유·삭제 기간은 실제 조사·운영 검토 대상으로 둔다. 후속 명세에서 검토 절차·책임 역할·비활성화 범위와 fallback을 정하되 미정 값을 임의로 채우지 않는다.

근거가 확인되지 않은 수치나 절차를 구현 편의상 과학적 기준으로 확정하지 않는다.

## 14. 문서의 적용 상태

이 문서는 서비스 원칙 0.2 설계안이다. 후속 명세 및 내부 적대적 재검토를 반영했으나 사용자 최종 확정이나 독립 전문가 검토 완료를 선언하지 않는다. 기존 자동 배치·연구 루틴·실행 API 문서와의 차이는 묶음의 재검토 문서에 표시한다. 문서 작성만으로 기존 구현이나 운영 설정이 바뀌지는 않는다.

후속 문서는 문헌 검토·근거 데이터 명세, 루틴 구성·응답 명세, 개인화 명세, 연구 업데이트·검증 명세 순으로 연결한다. 각 문서에는 관련 원칙 ID와 구현 상태를 기재한다.
