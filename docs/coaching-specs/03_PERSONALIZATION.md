# 기록 기반 개인화 명세

문서 ID: PER · 버전 0.2 · 2026-10-12 KST
상태: 설계안. 예시 수치는 계산 설명용이며 운동 처방이 아니다.  
연결 원칙: P03~P08, P10 · 선행: [루틴 구성·응답](02_PROGRAMME_CONTRACT.md)

## 1. 목적과 개인화 단계

과거 수행을 다음 선택에 활용하되 어떤 조건에서 어떤 기록을 반영했는지 재현할 수 있어야 한다. 현재 1RM에서 계산한 목표, 과거 실제 수행, 제안된 조정값을 구분한다.

| 단계 | 제공 내용 | 활성화 조건 |
|---|---|---|
| L0 기록 설명 | 목표 대비 수행·차이·누락을 보여줌 | 데이터 단위·상태 검증 |
| L1 과거 참고 | 비교 가능한 과거 기록과 차이를 보여줌 | 비교 가능성 규칙 검토 |
| L2 조정 제안 | 다음 부하·구성 후보와 이유, 선택권 제공 | 적용 조건·범위·fallback이 검토된 규칙 |
| L3 자동 반영 | 허용된 조정을 사용자 설정에 따라 다음 계획에 반영 | L2 조건 + 자동 적용 범위 동의·취소·감사·검증 |

단계는 개인화 품질 순위가 아니라 기능 범위다. L1 데이터가 풍부하다고 L2/L3을 자동 활성화하지 않는다. 현재 단계와 지원하지 않는 결정을 공개한다. 근거가 부족하면 낮은 단계로 fallback한다.

## 2. 비교를 위한 데이터

PER-01. 최소 연결: exercise_variant_id, 운동 장비와 중량 의미, 단측 계수, 당시 max_record_id와 측정/추정, programme/rule 버전, 계획·실제 세트, 반복·노력도·휴식, 시각과 결측 품질, 변경 사유, 다음 평가다.

profile은 현재값뿐 아니라 결정 시점의 스냅샷 또는 참조를 둔다. 사용자가 과거 정보를 수정하면 원 결정 이력과 현재 정정 상태를 구분한다. 주관적 회복 응답과 자기보고 1RM은 객관 검증값으로 표시하지 않는다.

회복 질문은 question_id/version, 응답 시점, 회상 기간, 척도 정의, 누락 사유, 사용하는 rule_id를 가진다. ‘잠을 잘 잤다’가 자동으로 특정 중량 감소/증가를 뜻하지 않는다. 그 연결을 검토한 규칙이 없으면 참고 정보로만 쓴다.

## 3. 비교 가능성 판정

PER-02. 비교 판정은 exact_context / contextual_reference / not_comparable / insufficient_data다. 검증되지 않은 종합 유사도 %는 제공하지 않는다.

exact_context는 정의된 비교 규칙상 동작·ROM·장비/중량 의미·계수·반복/세트 구조·노력도·휴식 제약·운동 순서 등 핵심 조건이 일치하고 필요한 값이 확인된 기록이다. 이것도 동일한 생리 상태를 증명하는 뜻은 아니다. 각 규칙은 어떤 조건이 핵심인지 명시한다.

일부 조건이 다르면 contextual_reference로 차이를 함께 보여준다. 다른 동작·측정과 추정 혼합·다른 기구의 스택·단측 계수 불명처럼 부하 비교 의미가 성립하지 않으면 not_comparable이다. 핵심 항목이 없으면 insufficient_data다.

시간 경과에 따른 기록 유효 기간, 허용 차이와 가중치는 규칙별 검토 대상으로 둔다. 아직 정하지 않았으면 자동으로 ‘최근 기록’을 골라 처방하지 않는다. 날짜순 표시와 자동 반영을 구분한다.

## 4. 종료 시 계산 계약

PER-03. 통계는 metric_id/version, 대상 세트 집합, 분자·분모·단위, 기준 계획 revision, 제외·결측 건수, 산출 가능 여부를 함께 반환한다. 하나의 숫자로 성장·충실도·회복을 합치지 않는다.

| 지표 | 계산/표현 | 제한 |
|---|---|---|
| 세트 중량 비율 | actual_kg / baseline_target_kg × 100 | 목표가 0·미정이면 null. 동일 중량 의미만 |
| 세트 반복 달성 | actual_reps / target_min_reps × 100 | 범위 목표는 범위를 함께 표시. 초과 수행은 그대로 보존 |
| 전체 최소 반복 달성 | Σ min(actual_reps,target_min) / Σ baseline_target_min × 100 | 확실한 skipped/not_attempted는 0, 미기록은 미확인 처리 |
| 동일 조건 세트 평균 중량 | Σ actual_kg / 기록된 세트 수 | 모든 동작을 섞지 않음. 세트별 기록을 함께 제공 |
| 반복 가중 평균 중량 | Σ(actual_kg × actual_reps) / Σ actual_reps | 명칭에 가중 방식을 명시, 총반복 0이면 null |
| 최소 휴식 부족 | max(0,target_min_sec-actual_sec) | 구간별 값·관측 방식. 미관측이면 null |
| 고정 휴식 차이 | actual_sec-target_sec | 긴 휴식과 짧은 휴식 구분. 효과 점수 아님 |
| 측정 기록 변화 | end-baseline, (end-baseline)/baseline × 100 | 동일 평가 방식·동작 조건, baseline > 0일 때 |

전체 최소 반복 달성은 결측 세트가 있으면 확정 % 대신 범위와 known_set_count를 보여준다. 결측 세트 기여를 0과 target_min으로 둔 하한·상한을 반환하고, 확정 기록이 늘면 범위를 갱신한다. 운동 진행 중에는 ‘지금까지 확인된 수행’으로 표시한다.

이 범위는 데이터 누락 때문에 계산 가능한 최소·최대이며 통계적 신뢰구간이 아니다. 분모가 정의되지 않는 AMRAP·시간 기반·등척성 세트에는 이 지표를 적용하지 않는다. 해당 목표 유형의 검토된 지표가 없으면 개별 수행값만 표시한다. 운동 전체 합계는 최소 반복 이행을 요약할 뿐 동작별 훈련 자극을 동등하게 취급하는 효과 지표가 아니다.

추가 세트는 원 계획 달성 분자에 넣지 않는다. 다른 동작으로 대체한 세트는 원 목표가 미수행된 상태와 추가 수행을 연결하고, 사전 검토된 대응 규칙 없이는 원 세트를 달성한 것으로 세지 않는다. 사용자 수정 후 active_target 대비 지표는 별도로 계산하고 baseline 대비 지표를 숨기지 않는다.

### 계산 예시: 훈련 추천이 아닌 기록 예제

동일 동작·동일 중량 의미, 목표 80 kg × 5회씩 3세트. 실제는 80×5, 75×5, 72×4이며 모든 기록이 확인된 경우:

- 목표 중량 대비: 100%, 93.75%, 90%.
- 최소 반복 달성: 14/15 = 93.33%.
- 세트 평균 중량: (80+75+72)/3 = 약 75.67 kg.
- 반복 가중 평균: (80×5+75×5+72×4)/14 = 약 75.93 kg.

둘 중 어떤 평균을 사용했는지 명시한다. 이 값들을 ‘성장률’, ‘논문 효과 달성률’ 또는 ‘다음 권장 중량’으로 자동 전환하지 않는다. 세트 순서에 따른 감소를 차트에서 보존한다.

## 5. 다음 결정의 절차

PER-04. 결정 순서는 입력 품질 확인 → 중단/적용 제외 조건 확인 → 규칙 적용 가능성 확인 → 과거 비교 판정 → 후보 산출 → 이유와 한계 표시 → 사용자 선택/허용된 자동 적용 → 결과 기록이다.

우선순위: 제공 중지·안전 관련 제약 > 적용 범위·입력 유효성 > 해당 프로그램의 검토된 규칙 > 해당 조건을 다루는 별도 검토 규칙 > 과거 참고 > 사용자 직접 선택. 둘 이상의 규칙이 상반된 처방을 내면 평균내지 않고 conflict로 자동 적용을 멈춘다. 제품 정책이라는 표기만으로 충돌을 무시할 수 없다.

DecisionRecord 필수값: decision_id, created_at, instance/revision, trigger_event_ids, baseline_refs, history_record_refs, missing/excluded_inputs, comparison_status, rule_ids/versions, evidence_refs, candidates, selected_candidate, selection_origin, fallback_reason, limitations, supersedes_id.

과거 기록의 자동 재사용은 숫자 선택 규칙도 검토돼 있어야 한다. 최고값·평균·마지막 성공값 중 하나를 편의상 선택하지 않는다. 사용자가 직접 과거 75 kg을 선택한 경우 user_override로 기록하고, ‘근거가 권장한 75 kg’으로 바꾸지 않는다.

사용자 확인 이후 실제 적용 직전에 입력 revision·규칙 버전·릴리스 상태를 재확인한다. 만료되거나 정정된 제안은 stale로 표시하고 재산출한다. 동일 decision_id의 동일 적용 요청은 같은 결과를 돌려주며 재시도로 중량 변경을 두 번 누적하지 않는다. ‘같은 입력’에는 기준 시각·모든 참조 revision과 선택 정책이 포함된다.

## 6. 상황별 기대 동작

| 상황 | 처리 | 금지되는 추론 |
|---|---|---|
| 처음 사용, 기록 없음 | 현재 기준 입력 또는 지원되는 준비 경로 | 평균 사용자 기록으로 1RM 생성 |
| 1회 반복 미달 | 실제 기록·이유 확인, 해당 규칙 있으면 제안 | 1회 미달을 정체·회복 부족으로 확정 |
| 반복 미달이 지속 | 비교 가능성과 누락·변경 확인, 승인된 평가 기준 적용 | 근거 없이 ‘3회 실패면 10% 감소’ 고정 |
| 초과 수행 | 실제값 보존, 검토된 진행 규칙만 적용 | 모든 운동에 동일 증량 폭 적용 |
| 휴식이 짧음 | 관측된 차이 표시, 다음 휴식 선택 지원 | 부족한 초를 근력 손실 %로 환산 |
| 중량 낮춤 후 목표 달성 | 변경 전후 기록 비교, 다음 결정의 후보 자료 | 달성했으므로 해당 중량이 최적이라고 확정 |
| 1RM 갱신 | 현재 계획 재산정 제안과 과거 기준 병렬 보존 | 과거 처방 덮어쓰기 |
| 쉬었다 복귀·부상/통증 보고 | 적용 가능한 복귀/중단 경로 또는 개인화 보류 | 과거 성공 중량 자동 재개 |
| 장비 변경·동작 대체 | 비교 지위 하향, 별도 기록 연결 | 동작 이름 유사성만으로 중량 이전 |
| 수면·회복 응답 누락 | 해당 규칙 입력 부족 표시, 다른 유효 기능 유지 | 누락을 정상 회복으로 가정 |
| 기록 정정·삭제 | 영향받은 분석·미적용 제안 무효화 후 재계산 | 이미 수행한 과거 계획을 소급 변경 |
| 프로그램 완료·중도 종료 | 종료 이유·수행률·측정 누락과 다음 선택 제공 | 완료자만 다음 분석에 사용 |

미달 이유의 답변을 강제해 거짓 이유를 입력하도록 만들지 않는다. ‘모름/기록 안 함’은 허용하되 그 정보에 의존하는 자동 처방은 제한한다. 통증 처리는 모든 이벤트 유형에서 일관되게 적용한다.

## 7. 회복 질문과 평가

PER-05. 질문별로 사용하는 규칙, 답변에 따라 달라지는 결정, 수집 빈도, 미응답 시 동작을 먼저 정의한다. 일일 체크인 없이도 기록 기능은 유지한다. 회복 정보의 통계적 연관만으로 감량 계수를 만들지 않는다.

프로그램 종료 분석은 출발 평가·세션별 계획/실제·변경 이력·종료 평가를 연결한다. 종료 평가가 없으면 수행 개선을 보고할 수 있지만 측정 근력 성장률은 계산하지 않는다. 연구 기간·대상·평가 조건과 개인 조건을 나란히 보여주며, 중간 관측이 없는 논문에서 주차별 예상 성장선을 만들지 않는다.

## 8. 유사 사용자·공유 결과지

PER-06. 초기 범위는 사용자 동의에 따른 자기 결과지와 사례 탐색이다. 유사 사례 기반 자동 처방은 별도 검증 전 비활성화한다. 사례에는 프로그램·규칙 버전, 시작 조건, 수행·변경·회복 기록의 완전성, 평가 방식·기간, 종료 이유를 연결한다.

공유와 집계 분석 동의를 분리한다. 민감한 프로필·정확한 시간·자유 서술은 기본 비공개이며 사용자가 공개 항목을 선택한다. 집계는 재식별 위험과 소표본 노출 기준을 사전 검토하고 기준 미정 상태에서는 공개 비교 통계를 제공하지 않는다.

사례 수, 해당 기간 시작자 수, 평가가 있는 사람 수, 탈락·미확인 수를 구분한다. ‘비슷한 사람의 성공 사례’만으로 효과를 추정하지 않는다. 추천 모델을 검증할 때는 동일 사용자의 기록이 학습·평가 양쪽에 섞이거나 미래 평가가 과거 결정에 사용되지 않도록 한다.

## 9. 인수 조건·미결정 값

PER-A01: 같은 입력·규칙 버전에서 동일 결과를 재현한다. PER-A02: 위 계산 예제를 재현하고 분모·결측을 표시한다. PER-A03: 연구·제품 규칙·사용자 선택 출처를 섞지 않는다. PER-A04: 비교 불가 기록이 자동 부하 제안으로 들어가지 않는다. PER-A05: 정정 후 미적용 제안의 stale 상태를 검출한다. PER-A06: 어떠한 수행률도 개인 효과 보장 문구로 연결되지 않는다.

기록 유효 기간, 허용 차이, 개인화 가중치, 정체 판정 기간, 자동 조정 폭은 여기서 숫자를 만들지 않는다. 각각 rule 후보의 blocking_parameter로 등록하고 값을 검토하기 전 해당 L2/L3 분기를 활성화하지 않는다. L0/L1과 사용자 직접 기록은 가능한 범위에서 계속 제공한다.
