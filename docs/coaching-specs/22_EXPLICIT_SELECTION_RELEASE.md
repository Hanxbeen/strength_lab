# 명시적 루틴 선택 범위 — 2026-10-18

## 결정과 한계

사용자 우선순위 ② 숙련도별 공급 / ③ 실제 선택·시작 응답을 연결한다.
전체 allowlist를 제거하지 않는다. backend/programme_access.py의 정확한 원문 정의 해시 4개에만 명시적 선택을 허용한다.
과학적 승인, 독립 전문가 심사, 개인 적합성 추천이 아니다. 원 JSON의 research_preview 표시는 유지한다.
이 문서는 구현·근거 정합성 검토이며 독립 전문가 승인 기록을 대체하지 않는다.
배포 완료 여부는 CURRENT를 따른다. 코드가 존재한다고 실제 앱 응답이 바뀐 것은 아니다.

낮은 세트 수를 낮은 난이도로 분류하지 않는다. 조건 충족을 효과·안전 보장으로 해석하지 않는다.

## 근거 및 제품 변경

- Petrizzo: https://www.asep.org/asep/asep/JEPonlineOCTOBER2018_Petrizzo.pdf
  Procedures와 기존 21번 검토. 네 종목 보존. 감독 없는 수행·사용자 작업 중량/휴식 선택은 제품 변경이다.
- Helms: https://pmc.ncbi.nlm.nih.gov/articles/PMC5877330/
  Participants/Procedures의 대상 범위, 두 실험군, 23훈련 회차와 검사 구분, 세트 조정·휴식 정의를 유지한다.
  연구자 중량 선정/감독을 사용자 입력으로 대체하는 한계가 있다.
- METD: https://pmc.ncbi.nlm.nih.gov/articles/PMC8435792/
  연구3/4의 모집 조건과 6주 구성. 소표본·준무작위 배정과 비교 한계를 유지한다.
  최소량을 보편적 최적 훈련이나 입문 처방으로 해석하지 않는다.
- 기존 source definition의 결과/한계/원문 locator를 응답에 포함한다.
  수행률을 연구 성장률로 변환하거나 원문에 없는 정체·통증 감량 계수를 만들지 않는다.

## API 계약

1. GET /v3/routines: 인증 필수. 정확한 공개 선택 해시와 활성 카탈로그 항목의 교집합만 반환.
   전체 회차/종목/세트/부하 규칙, 원 정의, 필수 입력 필드, 선택 식별자/버전을 반환.
   coverage는 실제 카탈로그에서 산출. 필터를 써도 전체 제공 범위 수치는 유지한다.
2. POST /v3/routines/preview: 저장하지 않고 입력 부족/적용 범위/첫 세션 준비 상태를 반환.
   중량이 아직 없으면 수치를 꾸미지 않고 needs_session_input을 반환.
3. POST /v3/programme-instances: 소유자 1RM 기록과 적용 조건을 다시 확인하고 접근 결정 버전을 고정 저장.
4. POST /v3/programme-instances/{id}/workouts: 원 정의·현재 제공 여부·입력·순서 재검증.
   이미 시작한 동일 요청 재시도는 유지하지만 철회 이후 새 세션은 차단.
5. 기존 v2 기록 API: 목표와 실제 중량·횟수·휴식·사유·중단을 별도 보존.

새 원문/해시가 생겨도 자동 공개되지 않는다. 범위 확장에는 별도 변경 검토와 테스트가 필요하다.
사용자 동의 플래그가 미지원 대상을 지원 대상으로 만들지는 않는다.
내부 연구 계정은 기존 연구 미리보기 용도이며 일반 사용자 적용 조건 검증과 구분한다.

## 적대적 검증 기준

- 정상: 7선택안 각각 미리보기→생성→시작→감량→기록→중단→재조회→다음 회차 응답.
- 반례: 무인증, 타인 기록, 누락 입력, METD 조건 불일치, 변경된 해시, 중지/누락된 카탈로그, 공개 목록 철회.
- 기존 전체 테스트는 건너뜀 없이 통과해야 한다.
- 실제 DB HTTPS 카탈로그와 로컬 API 검증은 실제 로그인/배포/Postgres 운동 저장 검증과 분리 보고.
- 입문 미지원, Helms 데드리프트 미포함, 여성 등 현재 제외 범위를 숨기지 않는다.
  모든 숙련도/인구집단 공급 완료로 선언하지 않는다.
