# 운동 기록에 연결되는 연구 해석 — 2026-10-13

## 이번 변경의 범위

휴식·훈련량·디로드 연구 3건을 자체 요약한 버전 데이터로 DB에 저장하고,
사용자 소유의 실제 운동 기록에 연결하는 읽기 전용 API를 추가했다.
새 루틴 3개, 검증 완료 연구 3개, 개인별 최적 처방 3개를 추가한 것이 아니다.
독립 검토·정정/철회 확인은 미완료이며 scientific_approval=false를 유지한다.
기존 Helms 프로그램의 세트·중량·5–7분 휴식 규칙을 이 데이터가 바꾸지 않는다.

## API 계약

1. GET /v3/context-evidence: DB의 버전별 연구 해석 자료.
2. GET /v3/workouts/{workout_id}/evidence?evidence_version={hash}&topic=auto:
   해당 사용자의 기록과 요청한 정확한 근거 버전을 연결.
3. topic은 auto/rest/volume/deload. volume과 deload는 명시적으로 요청할 때만 응답한다.
4. auto는 목표보다 짧게 직접 종료한 세트 사이 휴식에만 연구 설명을 연결한다.
   진행 중 휴식, 운동 종료로 중단된 휴식, 종목 전환 휴식에는 이를 자동 적용하지 않는다.
5. 미달 반복수·건너뛴 세트·미시도 세트를 분리한다. 한 세션으로 정체나 원인을 진단하지 않는다.
6. 통증 기록이 있으면 연구 해석 카드를 억제한다. 통증별 처방은 하지 않는다.
7. 응답에 policy_version, evidence_version, execution_revision, execution_hash를 포함한다.
   이는 응답 재현용 식별자다. 사용자에게 실제 표시했다는 영구 감사 로그는 아직 없다.
8. 연구 카드에 원문 링크, 검토 범위, 결과, 한계를 함께 넣는다.
   applicability=not_assessed_for_individual이므로 개인 적합성을 인증한 응답이 아니다.
9. prescription_change/growth_prediction은 null. 이 API는 운동·중량·휴식을 수정하지 않는다.
10. 버전 미존재·중단·DB 장애는 503. 다른 사용자의 운동은 연구 조회보다 먼저 404.
    근거 조회 장애가 기존 운동 기록 읽기/쓰기를 막아서는 안 된다.

## DB와 권한

coaching_context_versions에 내용 해시 버전을 저장하고 import는 ON CONFLICT DO NOTHING이다.
DB 관리 권한까지 불변으로 강제하는 트리거는 없으므로 운영자는 기존 payload 수정 대신 새 버전을 추가한다.
API는 payload와 버전 해시가 불일치하면 응답을 차단한다.
Supabase 지침에 따라 RLS, 명시적 SELECT 권한, SECURITY INVOKER RPC를 적용했다.
anon/authenticated의 INSERT/UPDATE/DELETE 권한은 제거했다.
개인 운동 데이터는 이 공개 연구 테이블에 저장하지 않는다.

실제 DB 조회: 패킷 1개, 연구 설명 3건.
버전: d3de5ab504cc578f295f5288a38f600e61a0ba4804a58f1a5e39f56a6e56a969
새 테이블 관련 보안 경고는 없었다. 기존 private research_internal 테이블 2개의
RLS Enabled No Policy INFO는 외부 접근을 허용하지 않는 의도적 기본 거부 상태다.
참고: https://supabase.com/docs/guides/database/database-linter?lint=0008_rls_enabled_no_policy

## 적대적 재검토

- 실패: 운동을 끝내며 타이머가 닫혔다는 이유로 휴식 부족이라 코칭할 수 있었다.
  수정: 자동 연구 연결은 between_sets + skipped 종료만 허용하고 회귀 테스트했다.
- 위험: 초록만 본 휴식 논문을 정밀한 처방으로 사용할 수 있다.
  차단: abstract_only와 검토 한계 노출, 중량·휴식 변경 금지.
- 위험: 세트 증가의 근비대 효과를 파워리프팅 중량 증가 보장으로 오인할 수 있다.
  차단: 근력 결과와 분리, 개인 정체 대응 공식 없음.
- 위험: 디로드의 종류를 합쳐 잘못 처방할 수 있다.
  차단: 완전 중단과 감량 훈련을 명시적으로 구분, 불확실성 구간 보존.
- 남은 결함: 범용적인 연구 설명이다. 개인의 적합성 판정·장기간 추세 기반 선택을 완성하지 못했다.
- 남은 결함: 근거 버전을 선택할 클라이언트, UI에서 한계를 읽기 쉽게 표시하는 화면,
  배포 서버 연결, 실제 사용자 대상 검증은 이번 범위 밖이다.
- 남은 결함: 통증/부상 의료 판단은 이 API의 역할이 아니다.
