# 진행 전략 재검토 및 실행 계획 — 2026-10-13

상태: 저장소 d2dea2e 기준 코드·명세 대조와 반례 실행. 독립 전문가 검토나 사용자 실험이 아니다.
이 문서의 우선순위가 07/08 문서의 다음 작업 순서를 대체한다. 과거 구현 기록은 삭제하지 않는다.

## 판정

일부 매몰됐다. 재사용 가능한 기록·출처·버전 기반은 만들었지만,
연구 추출 및 설명 API의 증가를 실제 코칭 경험의 전진처럼 다루기 시작했다.
서비스 원칙은 유지한다. 구현 순서와 완료 기준을 바꾼다.
논문을 더 모으는 일과 앱 연결 중 하나만 택하지 않는다.
지원하려는 한 사용자 흐름에 필요한 근거와 실행 경험을 함께 완성한다.

## 매몰 원인과 중단할 작업

- 측정하기 쉬운 논문 수·API 수·테스트 수가 핵심 흐름 완성도를 대신했다.
- 접근 가능한 연구 한 편을 충실히 재현하는 일이 지원 사용자와 SBD 전체 설계를 대신했다.
- 근거 공백을 정직하게 밝히는 것과 사용자가 다음에 무엇을 할지 도와주는 것을 함께 만들지 못했다.
- 별도 context API를 더 늘리면 기존 guides와 설명·안전 판단이 계속 중복될 수 있다.
- 문서마다 미결정을 추가하면서 담당 산출물·종료 조건 없는 검토 대기가 누적됐다.

보류: 새 설명 전용 API, 고정 개수 논문 수집, 추가 로고/레벨 디자인,
유사 사용자 추천·커뮤니티, 범용 규칙 DSL, 실사용 검증 전 모든 수준 지원,
새 연구를 바로 공개하는 자동화. 기존 자산 삭제는 하지 않는다.

## 개선된 진행 순서와 완료 기준

### S0 — 신뢰 가능한 실행 바닥
선행 없음. 다음 구현의 첫 작업.
- 통증·휴식·결측 반례 수정 및 버전 영향 기록.
- 공개 가능 상태와 내부 연구 시연 상태 분리.
- CI 의존성과 원문 검증 누락 해결, 기존 자동 배치의 실제 쓰기 범위 확인.
완료: 동일 사건에 API별 상반된 안내 없음; 미검토 공개 우회 차단;
깨끗한 실행 환경에서 필수 테스트의 실행/미실행을 구분한 결과.
이 단계의 완료는 과학적 검토 완료가 아니다.

### S1 — 지원 대상과 하나의 완결된 코칭 흐름
S0의 구현과 함께 설계 가능, 실제 공개는 S0 이후.
초기 가설: 바벨 SBD 경험이 있으며 중량 향상을 원하고 기본 동작을 독립 수행하는 성인,
한 종류의 훈련 환경과 주당 일정부터 지원.
이 가설의 대상·일정·제외 기준은 근거 검토로 확정한다. 성별/나이를 특정 연구 편의대로 확정하지 않는다.
- 의사결정 지도: 시작 부하 / 다음 세트 / 다음 세션 / 휴식 / 일정 변경 / 평가.
- 각 결정에 직접 근거, 종합 판단, 제품 규칙, 사용자 선택, 아직 지원 안 함을 명시.
- 완주 예시와 감량·일정 지연 예시를 같은 흐름으로 설계.
완료: 사용자가 시작부터 다음 운동까지 해야 할 행동, 필요한 입력, 예외와 출처가 명확함.
해당 범위를 뒷받침하지 못하면 범위를 좁히거나 연구 재현 시연으로 명시한다.

### S2 — 결정 중심 근거 묶음
S1 결정마다 기존 후보를 선별하고 빠진 핵심·상반 연구를 추가 탐색.
먼저 SBD 직접 대상 및 관련 결과를 확인하고, 간접 근거는 적용 근거와 한계를 별도 기록.
논문마다 별도 루틴을 만드는 대신 보고서-연구-실험군-결과-규칙 연결을 정리한다.
출판 시점·검색 순위·논문 수를 품질 점수로 쓰지 않는다.
전문 접근 불가, 정정/철회 미확인, 조건 미보고를 숨기지 않는다.
완료: 초기 모든 결정에 검토된 규칙 또는 구체적인 사용자 선택 경로가 있음.
추가 검색이 어떤 결정을 바꿀 수 있는지 설명되지 않으면 그 수집은 우선순위를 낮춘다.
검토자 역량·범위·책임을 실제로 확보하기 전 독립 승인을 선언하지 않는다.

### S3 — 기존 기록을 다음 행동에 연결하는 최소 구현
S1/S2에서 정의한 한 흐름만 구현.
- 같은 프로그램·동작의 이전 목표/실제/변경 사유 표시.
- 비교 조건이 다른 기록의 차이 표시 및 자동 환산 제한.
- 사용자가 과거 중량을 선택하면 출처=user_choice로 기록.
- 검토된 조정 제안은 생성→확인→적용→수행을 연결하고 수정/취소·stale 처리.
- 종료 평가와 미측정 상태, 다음 계획 선택 연결.
완료: 기록이 다음 선택에 영향을 준 이유를 재현 가능한 예제로 확인.
단순 평균·최고 중량·논문 평균 성장률로 처방하지 않는다.

### S4 — iPhone에서 흐름 검증
S3가 전부 끝날 때까지 화면 작업을 기다리지 않는다.
S0 이후 L0/L1 흐름부터 한 사용 경로를 앱에 연결하고 단계적으로 확장.
기존 디자인 토큰 유지; 논문 상세는 펼쳐보기, 다음 행동이 첫 화면.
실제 저장/재실행/오프라인 복구 경계와 삭제·정정 기능 포함.
완료: 1RM 입력→운동→감량→휴식 단축→중단/완료→재실행→다음 세션을 실기기에서 수행,
근거 설명과 목표/실제 차이를 사용자 스스로 구분할 수 있음.

### S5 — 사용성 검증과 확대 결정
현재 경쟁 우위와 효과 우월성은 가설이다.
관찰 항목: 도움 없이 다음 행동 선택, 입력 누락·오류, 근거 설명 이해,
기록/복구 성공, 이전 기록 참고의 실제 유용성, 중도 이탈 이유.
통과 조건은 관찰 전에 기록하고 사후 결과에 맞춰 바꾸지 않는다.
사용성 검증과 근력 효과 검증은 별도다. 기록 앱 대비 선택 유용성이 확인되지 않으면
근거 카드 확대를 멈추고 결정 흐름을 수정한다.
다양한 사용자·일정·보조 운동·회복·정체·새 연구 감시는 검증된 흐름부터 확대한다.

## 이번 검토에서 하지 않은 일
문서·계획 수정과 반례 확인만 수행했다. 위 결함의 제품 코드 수정,
운영 배치 중단, DB 승인 상태 변경, 앱 배포는 하지 않았다.
S0부터 수정한 뒤 각 항목에 구현 커밋과 검증 결과를 붙인다.
