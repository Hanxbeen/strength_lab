# 루틴 중심 제품 흐름 재설계 — 2026-10-14

상태: 사용자 캡처, 현재 Swift/Python 코드, 운영 DB RPC 응답을 대조한 설계안. 제품 구현·루틴 공개 완료가 아니다.

## 문제와 책임
이전 작업은 기록 엔진과 검토 경계에 집중한 반면, 선택 가능한 근거 기반 루틴을 제공하는 핵심 경로를 완성하지 않았다. 테스트 통과·설치 성공은 그 공백을 해소하지 않는다. 기존 연구 제외 사유를 일반 사용자 루틴 목록에 노출한 것은 제품 정보 구조 오류다.

## 확인 사실
- Services.CatalogStore는 /v1/protocols 또는 public.research_catalog를 호출한다. v3를 읽지 않는다.
- 2026-10-14 DB 조회: research_catalog.items=0, studies=3. 전체 응답과 집계 쿼리로 재확인.
- coaching_source_catalog.items=1, status=research_preview. Helms 2018 연구의 두 실험군이며 독립 논문 두 편이 아니다.
- 해당 연구 정의는 scientific_approval=false, 교정·철회 검토 및 종합 검토 미완료 표시가 있다.
- backend/coaching_api.py는 /v3/research-programmes를 제공한다. 신규 인스턴스·운동은 서버 allowlist에 제한한다.
- 02_PROGRAMME_CONTRACT의 /v3/programmes와 readiness 등 전체 목표 계약은 구현 완료되지 않았다.
- ApprovedHomeView.ResearchStudyDetail은 제목·원문 링크·실행 제외 사유만 표시한다. 실질적인 연구 요약/코칭 근거 상세 화면이 아니다.

따라서 원인은 단순 통신 오류나 버튼 상태가 아니다. 공개할 프로그램 정의/릴리스, 사용자용 응답 계약, 앱 연결의 세 층이 미완료다. DB에 아무 데이터도 없다는 설명도 틀리다.

## 유지할 원칙과 바꿀 제품 구조
근거 부족한 프로그램을 공개 상태로 바꾸지 않는다. 그러나 공개 조건을 충족할 작업을 끝내지 않은 채 차단 화면을 제품으로 취급하지 않는다.

- 홈: 미선택이면 서비스 설명 한 줄 + 루틴 둘러보기. 선택 후에는 오늘 운동과 시작/이어하기가 첫 행동.
- 루틴: 실제 공개된 프로그램만. 기간·주당 횟수·동작·장비·중량 결정 방식·적용 범위를 먼저 표시.
- 상세: 전체 구성, 첫 운동 미리보기, 누구에게 검토된 구성인지. 근거는 펼쳐보기로 대상·비교·결과·한계·원문 제공.
- 준비: 선택한 루틴이 요구하는 조건/기록만 확인. 1RM을 등록해야만 둘러볼 수 있게 하지 않는다.
- 운동: 현재 동작·세트·중량·횟수와 한 개의 주 행동. 변경은 가능하고 원 목표는 보존.
- 결과: 목표/실제/휴식/미수행을 구분. 다음 세션 참고와 선택의 출처를 설명.
- 연구 검색 후보·추출 실패·실행기 미지원은 내부 검토 화면. 사용자 루틴 목록을 채우는 대체 콘텐츠로 쓰지 않는다.
- 초기 소개·최대중량 등록·체험 안내를 같은 비중의 큰 카드로 중복 배치하지 않는다.
- 하단 내비게이션은 본문을 가리지 않는 고정 영역. 색/간격/타입은 기존 토큰 유지, 액션만 차콜 강조.

## 공개 목록과 시작 권한의 계약
공개 카탈로그, 사용자 입력 준비 상태, 클라이언트 지원, 릴리스 상태는 별도다.
- 목록 반환: definition_id/version, release_id, 목표, 종목, 전체 기간/일정, 장비, 적용 조건, 중량 방식, evidence_summary, 지원 기능.
- source_reported / evidence_synthesis / product_policy / user_override를 보존.
- 입력 부족은 등록/확인 행동을 반환하고, 연구 미검토를 입력 부족처럼 보이지 않는다.
- API 장애/정상 빈 목록/조건 불일치/미지원 버전을 구분한다.
- 연구 미리보기는 공개 카탈로그로 자동 승격되지 않는다.
- 시작 요청은 서버에서 릴리스와 조건 재검사, 프로그램 버전과 당시 1RM을 고정한다.

## 실행 순서와 통과 기준
1. 첫 공개 프로그램의 범위를 결정한다. 현 Helms 추출은 스쿼트·벤치 8주 연구이지 전체 SBD 서비스가 아니다. 데드리프트를 임의 추가하지 않는다.
2. 해당 범위의 출처·원문 위치·상반 결과·미보고·변경 규칙·종료 평가를 검토한다. 구현 편의를 과학적 요건으로 둔갑시키거나 근거 없이 승인하지 않는다. 외부 독립 검토 미완료와 내부 검토 완료를 구별한다.
3. 검토 결론/적용 범위/허용 규칙/잔여 제한이 있는 버전 릴리스를 만든다. 단순 boolean 수정으로 대체하지 않는다.
4. 공개 목록→readiness→시작→수행→종료→다음 선택의 서버 계약을 한 프로그램으로 연결한다. 인증·지속 저장·오프라인 충돌 범위도 검증한다.
5. 아래 와이어프레임을 그 응답으로 연결한다. 가짜 루틴·하드코딩 목록으로 완성처럼 보이지 않는다.
6. 새 계정에서 루틴을 발견하고 조건을 확인해 시작 가능한지 검증한다. 기존 운동은 재시작/정정/다음 세션까지 확인한다.

## 와이어프레임 범위
../wireframes/routine-first.html은 공개 요건 충족 이후의 목표 경험이다. 모든 예시 입력/수행은 가상이며 실제 공개된 처방이 아니다. 첫날 65%·2세트×8회·세트 휴식5–7분은 현재 DB 연구 정의의 표시 예시다. 사용자의 실제 운동 권고가 아니다.
화면: 첫 홈 / 루틴 / 상세·근거 / 준비 / 진행 홈 / 운동 / 휴식 / 결과.
수치와 모든 상태를 구현한 완성 프로토타입이 아니라 정보 우선순위·클릭 흐름 검토용이다.
