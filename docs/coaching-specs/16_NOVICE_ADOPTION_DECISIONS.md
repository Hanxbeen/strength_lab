# 초급 근거 반영 및 SBD 변경안 판정

2026-10-16. 코드 구현을 위한 내부 근거 검토. 독립 전문가 승인 또는 공개 처방이 아니다.

## 이번 결정

초급 연구를 확보했다. 그러나 두 연구를 합쳐 '검증된 초급 SBD 루틴'으로 만드는 안은
채택하지 않는다. 원문에 명시된 선택을 미보고라고 취급해 무한 보류하지도 않는다.
Petrizzo의 주2/3회·휴식·증량 폭은 참여자 선택이 연구 구성에 포함돼 있다.
값이 하나로 고정되지 않았다는 이유 자체는 데이터화의 장애가 아니다.

원문과 검토 기록: `data/research/coaching/reviews/novice-sbd-20261016.json`.
각 수치의 보고 위치는 자료의 locator에 있다. 원문에 없는 값을 별도 연구에서
가져오면 새 제품 규칙이며, 단일 연구 재현으로 표시하지 않는다.

## 두 원문의 역할

| 자료 | 확보한 것 | SBD 전용 구성의 한계 |
| --- | --- | --- |
| Mao2023, DOI 10.3389/fphys.2023.1301535 | 8주·주2회; 세트/반복/휴식; 주차별 %1RM; 중간 재측정; 반복 미완수 후 다음 세트 -10% | S/B/로우 구성. 데드리프트로 바꾸면 다른 프로그램 |
| Petrizzo2018, JEP21(5):84–96 | 초급 남녀; 최대12주; 주2/3회 선택; 이전 할당 세트/반복 완료 후 직접 정한 증량 폭 | OHP와 벤치를 번갈아 수행. 핵심 결과는 스쿼트 진행 지속성, SBD 전체 효과 보장이 아님 |

- [Mao 원문](https://www.frontiersin.org/journals/physiology/articles/10.3389/fphys.2023.1301535/full)
- [Petrizzo 원문](https://www.asep.org/asep/asep/JEPonlineOCTOBER2018_Petrizzo.pdf)

Mao의 후반4주 중량은 중간 재측정 기준이다. 최초1RM을 계속 사용하면 원문과 다르다.
훈련8주와 연구 일정의3–10주를 혼동하지 않는다. TS/RR의 총 반복은 같아도
세트/휴식 구조는 다르다. 보고된 휴식값에서 3×120=360초, 7×51=357초이므로
동일 시간을 맞추려고 51초를 임의 수정하지 않는다.

Petrizzo는 58명 모집, 18명 기타 이유 제외, 40명 분석 중24명 완료다.
60%는 분석대상 분모이며 전체 모집자 완료율로 표현하지 않는다. 정체15명과
부상 중단1명도 남긴다. 완료자 회귀식은 개인 증량 처방으로 승인하지 않는다.

## 실제 변경안 판정

| 항목 | 판정 | 다음 구현에 주는 제약 |
| --- | --- | --- |
| OHP 삭제 | 제품 범위상 유지 | 원문 구성은 증거로 보존하되 실제 운동에는 넣지 않는다 |
| OHP 자리를 벤치로 대체 | 미채택 | 벤치 빈도/볼륨이 증가한다. 단순 삭제와 구분해서 검토 필요 |
| 로우를 데드리프트로 대체 | 미채택 | 동작/피로/전체 볼륨이 달라짐; 동일 효과 가정 금지 |
| 1RM×고정 비율로 Petrizzo 시작 중량 산정 | 미채택 | 감독하 5회 수행 평가를 1RM 비율로 임의 대체할 근거 부족 |
| 완료 후 사용자가 정한 증량 폭 적용 | 원문 선택 구조 보존 | 원 할당 전체 세트/반복의 완료 확인 필요; 한 세트 성공으로 충분하지 않음 |
| 실제 감량 후 완료를 원래 목표 완료로 처리 | 미채택 | 변경 전 목표/변경 후 목표/실제 수행을 분리해 판단해야 함 |
| 모든 미완수에 -10% 적용 | 미채택 | Mao 문맥 외 확장. 통증/자세/시간/장비를 힘 부족으로 추정하지 않음 |
| 긴 결석 후 자동 재시작/델로드 | 미채택 | 원문 부재. 개인 이력 확인과 직접 선택 경로를 별도 정의 |

## 다음 단일 실행 작업

먼저 SBD 전용 주간 구성과 감독 없는 시작 부하 선택의 적용 근거를 결정한다.
OHP 제외만 한 안은 벤치 빈도를 유지하지만 원문의 전체 훈련량을 줄인다.
OHP를 벤치로 바꾸는 안은 벤치 빈도를 늘린다. 둘을 같은 변경으로 취급하지 않는다.
어느 쪽도 이번 문서에서 효과·안전성을 승인하지 않는다.

이 두 결정이 해결되면 기존 엔진에 **한 개**의 명시적 제품 구성으로 연결한다.
확정해야 할 입력은 종목별 시작 중량·판정 출처, 주간 횟수/순서, 사용자 증량 선택,
휴식, 변경 후 완료 처리다. 새 설명 API나 범용 규칙 엔진은 만들지 않는다.
미완수 기록/직접 변경/종료는 기존 수행 원장을 사용한다.

## 검증과 남은 경계

신규 테스트는 주차별1RM 참조, 세트/휴식값, 탈락자 분모, 원 종목 보존,
미검토 자료의 실행기 유입 차단을 확인한다. 데이터 무결성이지 효과 검증이 아니다.
이번에는 실제 프로그램 DB/카탈로그/API/iOS를 변경하지 않는다.

2. 감독하 5회 평가 없이 시작하려면 어떤 별도 절차가 필요한가?

5. 위 결정을 누가 어떤 범위에서 검토해야 사용자 공개로 전환할 수 있는가?
