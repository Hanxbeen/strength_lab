# 사용자 시나리오 중심 공급·코칭 인수 기준
날짜: 2026-10-17
상태: 요구사항/작업 순서 확정안. 구현·공개 승인 완료 아님.
SERVICE_PRINCIPLES 유지. 이번 사용자 지시에 따라 09의 초기 대상 가설을 입문까지 확장한다.
15의 공급 공백을 대체하지 않고 구체화한다. 서버 연결 우선이라는 CURRENT의 안내보다 이 순서를 우선한다.

## 문제와 완료 단위
논문 추출/내부 어댑터/DB 적재는 사용자 기능 완료가 아니다.
완료 단위는 사용자 조건 → 오늘 행동 → 실제 수행/변경 → 종료 설명 → 다음 운동이다.
실행 가능한 코칭을 기대한 사용자에게 연구 제목과 실행 불가 사유만 보여주는 경로는 완료로 인정하지 않는다.
미검토 자료를 공개해서 빈 화면을 해소하지 않는다. 교육과 실행 루틴, 연구 참고를 분리한다.

## 사용자 시나리오
구간은 제품 설계이며 검증된 숙련 척도가 아니다. 종목별로 평가하고 모름을 보존한다.
| 시나리오 | 사용자 질문 | 필수 제공 | 종료/다음 행동 | 현재 공백 |
|---|---|---|---|---|
| 입문: 자세/장비 사용 모름 | 어디서 무엇부터 하나? | S/B/D 준비, 장비 설정, 동작 시범, 짧은 큐, 흔한 오류, 중단/도움 요청, 쉬운 연습 경로 | 연습 내용·어려운 점 기록, 같은 동작 재연습 또는 다음 단계 | 교육 콘텐츠·검토·전환 기준 미완성 |
| 초급: 독립 동작 가능, 증량 경험 적음 | 얼마로 시작하고 언제 올리나? | 1RM 없는 시작 경로, 가벼운 시도와 부하 선택, 주간 계획, 증량/유지/미완료 규칙 | 실제 수행과 규칙으로 다음 회차 제안·선택 | 기존 직접 선택 시제품은 자동 시작/진행 근거 부족 |
| 중급: 규칙적 훈련, 진행 둔화 | 무엇을 바꿔야 하나? | 최근 수행, 일정, 강도·훈련량·휴식 조건에 맞는 구성 | 여러 회차 추세와 비교 조건, 검토된 조정 선택 | 적합성·정체 대응 규칙 공백 |
| 숙련: 노력도 조절 경험, 목표 특화 | 피로와 SBD 우선순위를 어떻게 조절하나? | 근거 대상에 맞는 주기/자율조절 구성, 노력도·변형 종목 조건 | 계획 대비 수행과 블록 평가 | METD 등 내부 정의 존재, 일반 추천 미완료 |
| 대회 준비 | 일정에 맞춰 최고 기록을 어떻게 준비하나? | 별도 검토된 피킹·테이퍼·측정 계획 | 대회/평가 후 재진입 | 별도 미지원, 숙련자 루틴으로 대체하지 않음 |
| 혼합 경험/장기 휴식/장비 변경 | 내 경우는 어느 단계인가? | 종목별 경험, 현재 장비/최근 기록 확인 | 비교 가능한 정보만 재사용 | 단일 등급으로 해결 금지 |

입문을 모두 맨몸으로 제한하지 않는다. SBD 동작 학습에 맞는 무부하/가벼운 도구/장비 설정 경로를 검토한다.
빈 바도 자동으로 쉬운 중량으로 간주하지 않는다. 맨몸 연습을 바벨 SBD와 동등한 효과로 표시하지 않는다.
1RM 측정을 입문 필수 단계로 만들지 않는다. 영상 시청/체크박스/XP만으로 동작 숙달을 인증하지 않는다.
교육 시범의 출처, 제작 권한, 검토 기록이 필요하다. 앱은 실제 자세를 관찰하지 않은 상태를 명시한다.

## 근거를 세 종류로 연결
1. 프로그램 근거: 대상·전체 주간 구성·초기 부하·진행·평가·실험군/비교군.
2. 결정 근거: 부하 변경, 반복 미달, 휴식, 노력도, 재진입 등 특정 질문의 조건부 규칙.
3. 동작 교육 근거: 공신력 있는 기술 자료·지도 지침과 검토된 시범. 효과 비교 논문만으로 자세 교육 전체를 도출하지 않는다.
단일 논문이 모든 상황을 설명하도록 요구하지 않는다. 여러 연구 종합/제품 규칙은 원문 재현과 구분한다.
한 연구의 실험군 여러 개를 독립 논문으로 세지 않는다. 연구 결과의 불일치와 감독 여부를 포함한다.

## 수행 변경 사례와 설명 계약
예: 같은 고정 기준 1RM 100 kg에서 목표70 kg, 실제60 kg.
- 실제 강도는70%→60%, 차이는10%p, 목표 중량 대비 약14.3% 감소.
- 이 값은 근력 성장14.3% 손실 또는 운동 효과85.7%를 뜻하지 않는다.
- 50 kg이70%라면 기준1RM은 약71.43 kg이고60%는 약42.86 kg. 장비 반올림값을 따로 저장한다.
- 원 기준 1RM/날짜/측정·추정/목표/장비 반올림/변경 범위/실제 반복/휴식/세트 상태를 보존한다.
- 사유는 힘 부족/자세/통증·불편/장비/시간/기타/모름/건너뛰기, 복수 선택·정정 가능.
- 감량 후 더 수행했다는 사실은 기록할 수 있으나 '중단보다 성장에 유리했다'는 개인 인과 결론은 내리지 않는다.
- 통증은 단순 힘 부족과 분리. 감량하면 안전하다는 안내 및 사유별 임의 감량 계수 금지.
- 사유를 답하지 않아도 기록·종료 가능. 다음 판단을 바꾸는 정보만 추가 질문한다.

종료 응답:
1. 사실: 세트별 목표/실제, 반복, 실제 휴식, 변경 범위, 결측.
2. 해석: 어떤 근거가 어느 조건에서 관련되는지, 직접/간접 적용과 불확실성.
3. 다음 행동: 승인된 규칙의 유지/조정 제안, 추가 확인 또는 과거 수행을 참고한 선택.
4. 추적: 사용한 근거·규칙·기준·사용자 선택 버전.
근거가 없으면 설명을 만들어내지 않는다. 기존 참고/기록/선택까지 막지 않는다.

## 차트 계약
- 매회: 세트별 목표·실제 중량/반복/휴식. 결측과0회 구분, 단위·분모 표시.
- 기간: 사용자 실측/추정 구분, 동일 조건 변화. 연구 결과는 별도 참고 패널.
- 연구: 대상, 기간, 비교군, 분석 인원, 실제 보고된 시점/지표/불확실성/원문 위치.
- 연구의 전후 평균으로 가상의 주차별 성장 곡선을 만들지 않는다.
- 처방 수행률을 효과 점수로 표시하지 않는다. 서로 다른 동작/기준 중량을 평균으로 숨기지 않는다.

## 시스템 요구사항: 기존 엔진 확장
교육/훈련/연구 참고를 구분한 제공 유형과 다음 행동을 기존 응답 계약에 연결한다.
프로그램 적합성은 실행 준비·공개 상태와 별도로 판단하며, 사용자에게는 이해 가능한 이유를 보여준다.
근거·프로그램·교육·결정 규칙·실제 기록을 ID/버전으로 연결한다.
추천과 운동 시작은 같은 적용 조건을 재검사한다. 단계 라벨만으로 추천하지 않는다.
AI는 발견/초안 보조만. 런타임 안내는 검토된 데이터와 결정적 규칙으로 재현 가능해야 한다.
별도 범용 규칙 DSL/설명 전용 API를 먼저 늘리지 않는다.

## 실행 순서와 인수 기준
A. 사용자 요구/현재 공급/근거 공백 대응표: 이 문서. 완료는 설계에 한함.
B. 입문 교육 + 초급 실제 시작/변경/종료/다음 회차를 먼저 한 흐름으로 완성.
   기존 원문 검토와 기록 엔진 재사용. 교육 제작/부하 규칙의 근거가 없으면 해당 부분을 명시적 차단 항목으로 보고.
C. 동일 계약으로 중급/숙련 구성 적용. 단계별 미지원 범위를 공개 전에 확정.
D. Supabase 저장·Vercel·iOS 연결. 검토된 첫 흐름의 실제 HTTP/계정/앱 검증.
전체 근거가 다 모일 때까지 첫 흐름 연결을 미루지 않는다. 미검토 규칙으로 공개하지도 않는다.
기능 완료 보고에는 DB 조회 → 운영 API → 앱 시작 → 변경 → 종료 → 다음 운동 증거가 모두 필요.
문서·로컬 테스트·내부 DB 적재는 각각 해당 단계 완료로만 보고한다.

필수 인수 시나리오:
- SBD 경험/1RM 없음: 무조건1RM 입력이나 연구 실행 불가 화면으로 끝나지 않는다.
- S/B 가능, D 처음: D 학습 경로를 제공하고 세 종목을 숙련자로 일괄 분류하지 않는다.
- 목표70%, 실제60%, 힘 부족/미응답/통증: 기록은 보존하고 안내를 구분한다.
- 전 세트 완료/일부 완료/건너뜀/조기 종료/휴식 중 앱 종료/오프라인 재전송.
- 기록 정정/1RM 수정/단위 변경 후 과거 기준과 설명을 재현한다.
- 공개 후보 없음/추천 조건 미확인/네트워크 오류를 서로 구분한다.
- 연구의 직접 근거 없음: 근거 없음과 가능한 다음 행동을 함께 표시한다.

## 적대적 재검토
- 위험: 다시 문서만 추가. 대응: 다음 작업 산출물은 B의 교육 데이터와 첫 부하/진행 결정표; 새 현황 문서 추가를 성과로 세지 않는다.
- 위험: 연구 원문 완벽 재현 집착. 대응: 연구 종합 기반 제품 구성 허용, 조합의 검증 수준을 정직하게 표시.
- 위험: 입문자를 초급 처방의 낮은 %로 처리. 대응: 교육/기술 경험을 별도 축으로 관리.
- 위험: 경험 등급을 지나치게 세분화. 대응: 사용자가 해야 할 행동이 달라질 때만 구분.
- 위험: 근거 문구가 응원용 상식으로 끝남. 대응: 다음 행동을 바꾸는 규칙/추가 정보와 연결.
- 위험: 무감독 자세 학습 효과를 과장. 대응: 관찰하지 않은 숙달 인증 금지, 직접 지도 필요 상황 경로 검토.
- 위험: 모든 경우의 수를 약속. 대응: 명시적 지원 범위와 정보 부족/미지원 경로를 테스트.
- 위험: 연구 업데이트가 과거 기록을 변경. 대응: 버전 고정과 신규 채택 분리.
