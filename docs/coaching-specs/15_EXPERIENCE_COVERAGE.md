# 숙련도별 공급과 배정: 현재 공백 및 실행 순서

2026-10-16. 제품 설계/현황 점검. 새로운 과학적 처방 또는 출시 승인이 아니다.
이 문서는 당시 공급 공백 검토 기록이다. 현재 수량·다음 작업은 ../CURRENT.md와 20/21 문서를 따른다. 아래 표의 기본 SBD 공급 공백은 당시 상태이며 현재 네 종목 내부 구성2개가 추가됐다.

## 판정

현재 작업을 논문별 어댑터 추가만으로 계속하면 숙련도별 루틴 제공을 보장할 수 없다.
현재 엔진은 개별 연구의 입력/실행 조건을 검증하며, 숙련 구간을 판정하고 적합한
프로그램을 배정하는 엔진은 아니다. 이 차이를 숨기는 level 태그를 붙이지 않는다.

확인1: backend/programme_readiness.py는 recommendation_status=not_assessed를 반환한다.
확인2: sbd.py/metd.py/coaching.py의 개별 조건 및 저장된 원문 정의의 대상/종목을 대조했다.
공개 상태는 CURRENT와 소스 정의 기준이며 이번에 운영 DB를 재조회하지 않았다.

## 공급 범위: 제품 구간 가설이지 검증된 등급 척도가 아님

| 사용자 구간 | 현재 지원 근거/구성 | 아직 필요한 것 | 현재 판정 |
| --- | --- | --- | --- |
| SBD를 독립 수행하지 못하는 입문자 | 공개 가능한 SBD 프로그램 없음 | 동작 학습/도움받기 경로와 입문 대상 근거 | 자동 루틴 배정 미지원 |
| 동작은 익혔지만 체계적 훈련 경험이 적은 초급자 | 기본 SBD 공급 공백 | 시작 부하·진행·미완수 대응까지 묶인 근거/제품 구성 | 최우선 보완 |
| 꾸준히 SBD를 수행하는 중간 경험자 | PER 내부 조정안 후보; Helms는 S/B 두 종목 | PER 종목 변경 적합성, 전체 SBD 구성·적용 범위 검토 | 후보이지 추천 완료 아님 |
| 고강도/RPE 훈련 경험이 있는 숙련자 | METD 실행 어댑터, Zourdos 검토 자료 | 각 구성의 적합성·선택·예외 규칙 및 공개 절차 | 내부 실행/검토 단계 |
| 대회 특화/최상위 수행자 | 이들을 위한 별도 검토 완료 정의 없음 | 피킹·일정·회복·개별 맥락의 추가 근거 | 숙련자 연구를 그대로 확대하지 않음 |

이 표의 자료 배치는 검토 우선순위다. PER=중급, METD=고급이라는 자동 태깅은 아니다.
연구 표본이 숙련자라는 사실은 그 프로그램이 모든 숙련자에게 적합하다는 뜻이 아니다.
입문/초급 근거가 없으면 공개 목록을 빈 후보나 '운동 불가 연구'로 채우지 않는다.

## 배정에 필요한 세 층

1. 연구 대상/조건: 실제 참여자의 경험·종목·훈련 조건. 원문 사실로 보존한다.
2. 제품 적용 범위: 어떤 사용자에게 왜 제공할 수 있는지 검토한 범위와 변경점.
3. 사용자 현재 조건: 종목별 독립 수행 여부, 실제 훈련 이력, 사용할 수 있는
   주당 횟수/시간/장비, 기준 중량의 측정·추정·시점, 요구되는 경우의 RPE 사용 경험.

출석/XP/릴라 레벨은 3번을 대신하지 않는다. 큰 1RM이나 경력 연수 하나로 등급을
확정하지 않는다. 기준이 미검토인 현재 '초급=몇 년 이하' 같은 경계를 만들지 않는다.
S는 경험이 많고 D는 처음일 수 있으므로 전신을 단일 등급으로 확정하지 않는다.
미응답/불명은 초급·정상 회복으로 채우지 않는다. 실제 선택에 쓰이지 않는 질문은 수집하지 않는다.

## 기존 API에 연결할 계약 — 설계, 아직 미구현

새 설명 API를 추가하지 않는다. 기존 카탈로그/사전 확인 응답 안에서 다음을 구분한다.

- execution_readiness: 현재 구현의 입력/실행 전제 충족 여부. 추천과 별개.
- applicability: 연구 조건 일치/차이, 제품 적용 검토 상태, 누락 정보, 제외 사유.
- recommendation: 미평가 또는 검토된 규칙에 따른 후보. 근거/규칙 버전과 입력 참조 포함.
- release: 내부 시연과 일반 공개를 별도 판단. 입력 충족/사용자 동의로 공개 차단을 우회하지 않음.

경험을 확인할 자료가 부족하면 필요한 정보를 묻거나 사용자가 구성을 비교해 선택한다.
비교 선택 자체를 개인화 추천이라 부르지 않는다. 근거 없는 분기에서 자동 감량·증량을
만들지 않으며, 직접 변경은 원 목표와 별도로 기록한다.

## 수정된 작업 순서

1. **초급 SBD 공급 공백부터 보완.** 독립 동작은 가능하지만 체계적 훈련 이력이 적은
   사용자를 위한 프로그램 근거를 기존 코퍼스에서 먼저 찾는다. 새 검색은 부족한
   처방/진행/미완수 결정을 보완할 때만 한다. 2026-10-18 정정: OHP/보조 운동을 일괄 제외하지 않으며 원 연구 구성과 SBD 목표에 대한 역할을 확인한다.
2. **한 구성의 적용 결정 완료.** 직접 실행한 연구 구성과 여러 근거를 종합한 제품 구성을
   구분한다. 한 논문에 모든 예외가 없다는 이유로 영구 보류하지 않는다. 제품 조정은
   적용 조건·근거·한계·기록·중단 기준을 갖춰 검토한다. 임의 수치를 원문 사실로 쓰지 않는다.
3. **기존 실행 경로 연결.** 확보된 구성의 불변 정의를 DB에 저장하고 실제 API 응답에서
   기준 1RM→목표→수행 변경→휴식→종료→다음 선택을 검증한다. 후보 JSON 작성은 완료가 아니다.
4. **배정 규칙/경계 검증.** 숙련 구간 이름보다 실제 조건에 따른 후보/제외/추가 질문을 테스트한다.
   초급/숙련 같은 사용자 표시는 검토된 제품 규칙으로만 생성한다.
5. **앱 연결 및 확대.** 첫 지원 범위의 전체 흐름을 연결한 뒤 다른 구간을 추가한다.
   UI 재설계는 보류를 유지한다. 기존 데이터/어댑터/사용자 기록을 삭제하지 않는다.

Zourdos 숙련자 어댑터 추가는 1번보다 우선하지 않는다. 기존 PER를 초급이라고
재명명하거나 숙련자 처방의 %1RM만 낮춰 이 공백을 메우지 않는다.

## 완료 기준과 반례

- '숙련도별 제공 완료'는 출시할 각 구간에 검토된 구성과 배정 근거가 있을 때만 선언한다.
- 연구 표본 밖이라는 이유만으로 위험/효과 없음으로 판정하지 않는다. 제품 적용 미검토와 구분한다.
- 릴라 레벨 변경만으로 후보·중량이 바뀌지 않아야 한다.
- 초급인데 체중 대비 중량이 크거나, 경력이 길지만 D 경험이 없는 사례를 다룬다.
- 누락 이력/오래된 1RM/일정 불일치/이전 통증 기록은 필요한 확인과 가능한 다음 행동으로 연결한다.
- 실행 준비 완료라도 미검토 자료가 공개 또는 추천 완료로 승격되지 않는다.

모든 구간의 자동 조정 규칙은 없다. 4/5는 공개 흐름을 연결하며 검증해야 한다.
