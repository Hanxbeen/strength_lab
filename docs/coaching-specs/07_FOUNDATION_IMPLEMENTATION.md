# 코칭 근거 → 실행 API: 1차 구현 현황

작성: 2026-10-13 KST. 서비스 전체 완성이나 과학적 승인 완료를 뜻하지 않는다.

## 1. 실제 수집과 검토 범위

- 질문 12개로 Europe PMC 검색. 첫 페이지 최대 20건씩 231건을 받아 DOI/색인 식별자로 중복 제거한 후보 보고서 201개.
- 검색식·검색 URL·커서·전체 적중 수·반환 수·실패 상태를 discovery-20261012.json에 보존했다.
- 이 숫자는 적합성 검토를 통과한 연구 수가 아니다. 임상·급성 반응·다른 종목 등 제외 또는 간접 근거로 분류해야 할 자료가 포함된다.
- 결과가 최근 색인 자료에 치우쳤고 페이지 제한이 있으므로 기초 문헌을 포괄했다는 주장은 불가하다. 검색 랭킹/날짜는 근거 수준이 아니다.
- 명시적 DOI/PMID 검색으로 핵심 논문·정정 공지 12건을 별도 확보했다. 원문 검토 완료와 메타데이터 확인은 구분한다.
- 초록 전문은 권리 검토 없이 공개 저장소에 재배포하지 않는다. 초록 존재 여부와 해시, 원문 링크만 저장한다.
- CC BY가 확인된 Helms 2018 원문 XML은 저자·라이선스 표시를 유지하여 원문 스냅샷으로 보존한다.

## 2. 구현한 연구

Helms et al. (2018), DOI 10.3389/fphys.2018.00247, PMID 29628895, PMC5877330.
원문: https://pmc.ncbi.nlm.nih.gov/articles/PMC5877330/

연구 설계·표 2/각주·표 3·훈련 방법·참여자·탈락·결과를 대조했다.
이는 독립 도메인 검토가 아니며 scientific_approval=false이다.

- 8주, 주 3회. 마지막 주 마지막 날은 사후 평가이므로 훈련 23회, 팔별 총 128 working sets.
- 스쿼트와 벤치프레스만 다룬다. 데드리프트 전체 프로그램으로 광고할 수 없다.
- 1RMG: 시작 전 측정 1RM에 대한 비율, 특정 주차 조건부 증가, 실패 횟수에 따른 다음 세트 계산.
- RPEG: 목표 RPE 구간, 지난주 같은 세션의 수행 기록, RPE와 실패 횟수에 따른 다음 세트 계산.
- 두 연구 팔은 독립 논문 두 편이 아니다.
- 시작 24명/완료 21명, 통증·불편감 관련 탈락 2명, 가족 사유 1명.
- 두 군 모두 개선했으나 군 간 근력 변화 차이는 통계적으로 유의하지 않았다. 동등성을 입증한 것도 아니다.
- 논문에 실린 확률적 해석을 사용자의 성공 확률로 제공하지 않는다.

## 3. 연구와 제품 선택의 경계

원문 규칙: 주차별 세트·횟수·강도, 3/5/7주 조건부 증량, 세트 간 5–7분, 종목 간 10분,
순서, 과거 기록을 보여주는 방식, 원문에 명시된 실패/RPE 계산.

제품 선택·차이:
- 연구의 첫 주 RPE 중량은 연구자가 결정했다. 앱의 사용자가 직접 선택하는 방식은 재현이 아니라 명시적 변경이다.
- 워밍업은 사용자 선택으로 남겼다. 연구의 감독·평가 절차를 완전 재현하지 않는다.
- 장비 간격 반올림은 제품 규칙이다. 반올림이 감량/증량 방향을 없애면 실행 중량 제안을 확정하지 않는다.
- 중량 변경 제안은 자동 적용하지 않는다. 원 목표, 현재 선택, 실제 수행을 보존한다.
- 시간 부족/장비 문제/기술적 실패를 근육의 반복 실패로 간주해 감량 공식을 적용하지 않는다.
- 통증 기록이 있으면 해당 운동에서 계산 제안을 중지한다. 앱은 통증에 맞는 중량을 진단하지 않는다.
- 연속 일정 압축을 막는 최소 48시간은 보수적 제품 규칙이다. 원문의 '비연속일'과 동일한 수치 처방으로 인용하지 않는다.
- 일정 지연/수정 후 연구와 같은 결과를 기대할 근거는 없다.
- 연구 대상 밖의 사용자에 대한 별도 프로그램은 아직 구현하지 않았다. 연구 적용 범위와 서비스의 최종 사용자 범위는 다르다.

## 4. 구현 연결

- scripts/coaching_corpus.py: 질문별 후보 검색 및 로그
- scripts/coaching_foundations.py: 명시적 DOI/PMID 기반 핵심 후보 목록
- scripts/extract_helms2018.py: 원문 표 추출, 내용 해시, 근거 위치
- scripts/coaching_import.py: 비공개 후보와 원문 기반 프로그램을 원자적으로 적재
- research_engine/coaching.py: 기준 1RM 고정, 주차별 처방, 조건부 증량, 세트별 계산
- backend/coaching_api.py: DB 원문 카탈로그와 사용자별 인스턴스 API
- backend/coaching_store.py: 기존 기록 저장소와 인스턴스/세션 연결
- 기존 /v2/workouts/{id}/events: 중량 변경·실제 횟수·RPE·휴식·중단·완료 기록

새 API:
- GET /v3/research-programmes
- POST /v3/programme-instances
- GET /v3/programme-instances/{id}
- POST /v3/programme-instances/{id}/workouts

기존 진행 중 인스턴스는 원문·프로그램·1RM 버전을 고정한다.
새 세션은 원문의 suspended 여부를 확인한다. 이미 만든 세션의 동일 요청 재시도와 기록 열람은 유지한다.

## 5. 저장과 검증 경계

실제 Supabase에 광범위 검색 후보 201개와 별도 핵심 후보 12건을 적재했다. 중복 식별자 병합 기준 총 210개 보고서/213개 메타데이터 버전이며, 정정 공지를 독립 효과 연구로 세지 않는다. 추출 원문 정의는 1개다.
coaching_source_catalog RPC의 실제 반환과 anon 읽기, 후보 비공개, 일반 사용자 쓰기 금지를 확인했다.
운동 인스턴스·이벤트는 기존 WORKOUT_DATABASE_PATH SQLite 저장소를 사용한다.
이를 Supabase 사용자 운동 동기화 완료로 표시하면 안 된다.

보안 점검의 private table 'RLS enabled, no policy' INFO 2건은 의도적 기본 차단이다.
anon/authenticated에 해당 테이블 권한을 부여하지 않았다.
안내: https://supabase.com/docs/guides/database/database-linter?lint=0008_rls_enabled_no_policy

2026-10-13 전체 Python 테스트 127개 통과. 8주 23회/128세트 완주와 실제 DB 조회·권한 확인은 서로 다른 검증이다. 초기 전체 테스트는 테스트 환경의 Pillow 누락, 이후 한 테스트의 mock 핸들 오류로 실패했으며 이를 고친 뒤 재실행했다.
추가로 Git에 저장된 파일만 새 임시 디렉터리에 풀어 재검증: 111개 통과, 기존 v2 원문 캐시를 요구하는 16개 건너뜀. 새 코칭 테스트는 모두 실행됐다. 기존 캐시가 있는 작업 디렉터리에서는 127개 모두 통과했다.
테스트는 독립 도메인 검토 또는 운동 효과 검증을 대신하지 않는다.
원문 재추출, 원문 수치 예제, 8주 전체 진행, 소유권·인증·중단·단위·휴식·버전·정정 공백 등을 구분한다.
실제 API 서버 배포나 iPhone 앱 연결은 이번 변경에서 실행하지 않았다.

## 6. 적대적 검토: 아직 완료라고 할 수 없는 이유

1. 후보 201개는 과학적 기반 201편이 아니다. 적합성 선별, 원문 접근, 코호트 중복 및 상충 검토가 남았다.
2. 구현한 프로그램 2개 팔은 한 연구의 좁은 모집단·두 종목이다. 초보자·여성·데드리프트를 포괄하지 않는다.
3. 핵심 후보 12건은 메타데이터 확인 단계다. 수면·보조 운동·정체 대응을 수치 처방으로 변환하지 않았다.
4. 정정/철회 확인, 독립 검토, 장기 진행, 최종 평가·성장 비교, 사용자 기록 정정 및 클라우드 동기화가 미완료다.
5. 서버 API 코드와 DB RPC는 존재하지만 앱에서 루틴 선택→완료까지 연결한 출시 상태는 아니다.
