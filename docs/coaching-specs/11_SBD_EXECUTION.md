# SBD 데이터에서 종료 평가까지

2026-10-15 구현 기록. 현재 상태는 ../CURRENT.md를 따른다.
2026-10-18 정정: 과거 OHP/보조 운동 일괄 제외 해석은 폐기했다. SBD 목표에 필요한 원 연구 구성은 보존하며, 최신 네 종목 구성은 21_FOUR_LIFT_DELIVERY.md를 따른다. 아래 PER 구현 기록은 당시 범위다.

## 대안 검토와 결정
Superpowers brainstorming의 맥락 확인·대안 비교·경계 정의·자체 검토를 적용했다. 이미 사용자가 1~5 실행을 승인했으므로 같은 승인 질문을 반복하지 않는다.
논문마다 앱 실행기를 복제하면 Helms 종속 문제가 반복된다. 범용 AI 처방 생성은 출처와 미보고 조건을 감춘다. 선택한 방식은 원문 데이터·명시적 제품 조정·버전별 실행 어댑터를 나누고 기존 기록 엔진을 재사용하는 것이다.

## 제공 데이터
PER XLS 3개 훈련 시트의 4+4+2주를 전역 10주/30회로 구조화한다. 275개 수치 행, 반복 확장 시 515세트다. 이는 본세트만의 개수가 아니다. 워밍업/본세트 구분은 추출에서 미확정이다.
원본 XLS 두 개, 파일 SHA256, 시트와 셀, 원 종목 표기, 예시 kg를 보존한다. 별도 max day 시트는 훈련 회차에 추가하지 않는다. MAX 파일의 10주차를 임의 생성하지 않는다.
Front squat 표기를 원본에서 삭제하거나 오타로 확정하지 않는다. 실행하려면 numbered_sbd_adaptation_v1을 명시적으로 선택한다. 이는 번호가 붙은 SBD 블록으로 수행하는 제품 조정안이며 원 연구의 정확한 재현이나 검증된 대체 효과를 뜻하지 않는다. 내부 허용 계정만 시작 가능하다.

## 개인화와 기록
종목별 측정 1RM ID를 인스턴스에 고정한다. kg/lb는 기존 등록 계약에서 kg로 환산한다. 중량은 원문 비율×고정 1RM이며 장비 간격 반올림은 제품 규칙이다. 소수점 표현 정규화는 새 데이터 생성 단계에만 적용하며 기존 해시 정책은 변경하지 않는다.
휴식시간·추가 준비운동은 사용자 선택이다. 휴식의 출처를 source_reported로 잘못 표시하지 않는다. 실제 휴식·감량·0회·생략·중단·통증·사유 정정은 기존 이벤트 원장을 사용한다.
다음 같은 요일의 원 목표/실제/변경/사유/휴식을 제공한다. 이전 주의 강도·반복·세트가 다를 수 있음을 표시한다. 과거 중량을 자동 처방이나 새 1RM으로 바꾸지 않는다. 연구에 없는 실패·정체 감량 공식은 null이다.

## API/저장소
- 기존 /v3/programme-instances, workouts 경로가 어댑터로 분기한다. Helms 경로와 과거 기록을 유지한다.
- /v2/max-records 및 /v2/workouts/{id}/events를 재사용한다.
- /v3/programme-instances/{id}/evaluations가 프로그램 종료/조기 종료 평가를 저장한다.
- 동일 ID 동일 요청은 멱등, 변경 요청은 충돌이다. supersedes_id로 정정 버전을 추가하며 원본 평가를 지우지 않는다.
- 평가 이후 새 세션은 금지한다. 기존 세션 재요청/열람/사유 정정은 유지한다.
- post-test 미측정·추정·다른 조건·조건 불명을 구분한다. 같은 조건이라고 사용자가 보고한 실측만 변화량을 계산한다. 집단 평균 대비 달성률이나 인과적 성장 주장은 없다.
- 평가는 참조한 운동 revision과 이벤트 해시를 보존한다. 이후 사유 정정으로 과거 평가를 조용히 재계산하지 않는다.
- 원천 데이터는 Supabase 기존 source_versions에 적재한다. 구 RPC는 Helms 호환성을 유지하고 새 coaching_programme_catalog를 v3에서 사용한다. 사용 중지된 자료는 실행 API 목록에서 제외한다.

## 적대적 검토 및 출시 한계
한 연구의 구조화와 실행 가능성은 스포츠과학적 타당성 또는 다양한 사용자에 대한 충분한 루틴 공급과 다르다. 제품 조정안의 적합성 검토, 일별 원문 모순 해소, 더 넓은 SBD 근거 종합은 남는다. 사용자 동의는 과학적 근거를 대체하지 않는다.
이번 범위는 백엔드/데이터다. iOS는 기존 v1 카탈로그를 사용하며 신규 v3 서버 배포와 앱 연결은 완료로 보고하지 않는다. DB에 있는 내부 실행안과 앱에서 선택할 수 있는 공개 루틴을 구분한다.

## 구현·검증 순서
1. 원본 보존/셀 추출/해시 → scripts/extract_pilot_sbd.py, pilot2018-sbd.json.
2. SBD 실행/범위·출처·명시 선택 → research_engine/sbd.py, programme_dispatch.py.
3. 원장 연결/실제 휴식 출처/종료 평가 → backend/coaching_api.py, coaching_store.py, programme_evaluation.py.
4. 30회 전체 API 시나리오, 미완료·감량·휴식·정정·계정 경계 및 기존 회귀 테스트.
5. DB 읽기 후 해시/내용 재검증, 같은 DB 데이터로 시나리오 재실행, 커밋·푸시.

원천을 늘리는 다음 작업은 이 특정 논문의 모든 문제 해결에 종속시키지 않는다. 실제 사용자 결정(시작 부하/볼륨·빈도/진행/피로/평가)을 기준으로 다른 SBD 직접 근거와 상반 결과를 검토한다.
