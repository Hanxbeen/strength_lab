# SBD 공급 근거: 확보된 처방과 채택 결정

2026-10-15. 내부 원문 대조이며 독립 스포츠과학 승인 또는 사용자 공개가 아니다.

## 이번에 확보한 것

Zourdos의 HSP/HPS 6주 SBD 구성. 학위논문 Table5(인쇄 50–51쪽,
PDF 65–66쪽)를 화면과 추출 텍스트로 대조하고, 학술지 Training Protocol과
두 번째로 확인했다. 6주 훈련과 검사 포함 8주 연구를 구분한다.

- [학위논문 공식 기록](https://repository.lib.fsu.edu/islandora/object/fsu%3A183214)
- [학술지 원문](https://journals.lww.com/nsca-jscr/fulltext/2016/03000/modified_daily_undulating_periodization_model.24.aspx)
- DOI: 10.1519/JSC.0000000000001165

`scripts/build_zourdos_review.py`는 수동 검토한 사실을 결정적으로 전개한다.
AI 추출기나 승인기가 아니다. 결과: `data/research/coaching/reviews/zourdos2016.json`.
공유 처방 42행, 구성별 18회차/150본세트. 두 구성 및 두 출판물을 독립 연구
네 편으로 세지 않는다. 원문 PDF는 저작권 재배포 허가가 확인되지 않아 커밋하지 않는다.
출처 URL·파일 해시·페이지를 남기며, 로컬 원문은 `--source-pdf`로 대조할 수 있다.

## 데이터가 답하는 것과 답하지 못하는 것

| 결정 | 확보한 내용 | 남은 판단 |
| --- | --- | --- |
| 주간 배치 | HSP/HPS 순서, 비연속 주3회, S/B 주3회·D 주1회 | 장기 결석·회차 생략 후 재진입 |
| 시작 부하 | H 75%, P 80%, S 85% 1RM | 장비 반올림·준비운동·기준 1RM 갱신 |
| 반복 | H 8회, P 1회, S 실패까지 | 실패를 앱에서 판정할 방법과 중단 선택 |
| 주차별 진행 | 세트·강도 변화 표 확보 | H의 2–6주차 증량 판단 조건 |
| 휴식 | 훈련 휴식값은 확인되지 않음 | 사용자 선택/제품 정책과 근거를 별도 검토 |

학술지는 H 부하를 유지 또는 5/10 lb 증가시켰다고 보고하지만, 어떤 수행이면
어느 값을 적용하는지 명시하지 않는다. 인용된 Mann2010의 APRE를 그대로
이식하면 이 연구의 재현이라고 할 수 없다. 원문의 IA를 null로 남기고
선택 가능한 숫자를 자동 추천값으로 승격하지 않았다.

본문에는 P 85%가 2–3주로 적혀 80%의 1–2주와 겹치고 4주가 빠진다.
Table5는 3–4주로 표시한다. 데이터는 표를 전사하되 충돌을 함께 남겼다.
저자의 공식 정정으로 표현하지 않는다. 학위논문 Table6의 HSP 중복 표기도
순서 결정의 근거로 사용하지 않았다.

## 적대적 채택 검토

1. **기본 루틴 확보라는 목표를 충족했는가? 아직 아니다.** 대상자는 경력 5년 이상,
   S/D 2배 체중·B 1.25배 체중 기준의 숙련 남성이다. 이 표본을 일반 사용자의
   자격 기준으로 만들거나 초보자에게 적합하다고 확장하지 않는다.
2. **정보만 모으는 이전 패턴인가?** 실행에 필요한 주차별 수치를 확보한 진전은
   있다. 그러나 새 API·미리보기 화면을 추가해 공급 공백이 해결됐다고 세지 않는다.
3. **논문이 모든 예외를 설명해야 하는가? 아니다.** 휴식·장비·일정 등의 공백은
   명시적 제품 규칙/사용자 선택으로 처리할 수 있다. 부하·노력도 변경은 별도 검토가
   필요하다. 연구에 없다는 이유만으로 후보를 영구 보류하거나 무한 검색하지 않는다.
4. **효과가 일반적인가?** 작은 숙련 남성 표본이고 평소 훈련 대조군이 없다.
   단기간의 구성 비교를 개인 성장 보장이나 최적 루틴 증명으로 사용하지 않는다.
5. **중복 근거인가?** 학위논문과 학술지의 설계·표본 특성이 겹친다. 다만 학술지에
   2013 팀이 추가 언급돼 정확한 코호트 동일성은 미확인이다. 독립 재현으로 합산하지 않는다.

## 완료 경계와 다음 실행

이번 완료: 출처 전사 → 행/회차 구조화 → 누락·충돌 보존 → 실행기 유입 차단 검증.
미완료: 새 프로그램 DB 적재, 실행 어댑터, 공개 승인, 서버 배포, iOS 연결.
기존 3개 활성 내부 자료와 실행 계약은 변경하지 않는다.

다음 작업은 또 다른 설명 API가 아니다. 현재 후보 중 실제 지원하려는 성인 SBD
경험자에게 적용할 한 구성을 고르고, 아래 5개 의사결정을 한 장에서 끝낸다.
각 결정을 `원문 그대로 / 명시적 제품 조정 / 사용자 직접 선택 / 지원 제외`로
정한 뒤 기존 엔진으로 연결한다. 이 연구의 누락 임계값을 찾는 검색은 이번 단계에서
중단한다. 새로운 원문/저자 보충자료가 생기면 재개한다.

1. 첫 사용자에게 이 고강도 구성과 기존 PER 중 무엇을 제공할 수 있는가?
2. 시작 중량이 과하면 중단·직접 감량·다음 회차 중 무엇을 지원하는가?
3. 조정 규칙이 없을 때 과거 수행을 보여주고 직접 선택하게 할 수 있는가?
4. 원문과 달라진 휴식·중량·횟수가 종료 평가에 보존되는가?
5. 어떤 적용 조건을 확정하면 DB→API→앱 연결을 시작할 수 있는가?
