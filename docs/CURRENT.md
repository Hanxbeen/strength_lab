# 현재 상태 — 2026-10-14

이 문서가 작업 재개 진입점이다. 과거 완료 보고보다 현재 코드·테스트·이 문서를 우선한다.

## 활성 경로
- iOS 진입: ApprovedHomeView → GuidedWorkoutView → Services.WorkoutStore.
- 기록은 계정별 로컬 원자적 스냅샷. 수동 백업/복원 경로 유지.
- WorkoutReasons / WorkoutReasonSheet: 변경 사실과 버전별 자기보고·정정 이력 분리.
- Python: backend/workout_api.py + workout_store.py + research_engine/workout.py.
- 연구 시연: backend/coaching_api.py; 서버의 COACHING_PREVIEW_OWNER_IDS 허용 계정만 신규 실행.
- 연구 설명: context_api.py; 처방 변경 없음.
- 연구 수집: scripts/coaching_corpus.py. 검색 후보는 공개 루틴이 아니다.

## 중요 경계
iOS는 아직 기존 공개 카탈로그 RPC와 로컬 기록 엔진을 사용한다.
Python v3 연구 시연 실행과 iOS의 기록을 서버에서 동기화하는 연결은 완료되지 않았다.
동일한 사유 코드·자기보고 의미를 공유하되 Swift Codable과 Python 이벤트 형식은
직접 호환되는 전송 포맷으로 광고하지 않는다. 실제 전송 어댑터·배포 서버·충돌 검증이 필요하다.
체험 루틴을 과학적 검증 완료 루틴으로 변경하지 않는다.
초기 사용자에 대한 자동 처방 확대는 근거 검토 이후 별도 작업이다.

## 이번 구현
- 중량 변경 먼저 저장, 사유 칩은 선택 입력. 복수 사유·모름·건너뛰기 지원.
- 통증 선택 시 진행 일시정지; 명시적 재개/종료. 통증별 중량 처방 없음.
- 사유 정정은 이전 응답을 보존하고 직전 응답 ID를 확인한다.
- 완료 후/재시작 후 사유 정정, 실제 휴식 조회, 같은 루틴·회차의 과거 참고.
- 최초 설정 중량과 실제 중량을 분리. 이전 중량은 사용자 직접 선택으로만 재사용.
- 사유 입력을 하지 않아도 실제 반복을 저장하며, 수행 0회도 별도로 기록 가능.
- Python도 reason_record 이벤트를 종료 뒤 정정 가능. 기존 events를 덮어쓰지 않는다.

## 제거/유지

폐기된 UI 스튜디오 및 와이어프레임, 오래된 RFP/상태 문서, 옛 수동 게시 workflow.
유지: EditSetSheet와 BackupView는 RecordMaintenanceView로 이동.
카탈로그 v1, 연구 어댑터 v2, 구버전 기록 재생, DB migration 및 기존 회귀 테스트는
현재 클라이언트/과거 데이터/원문 검증에서 사용하므로 호환 경로다. 새 구현의 출발점이 아니다.
과거 마이그레이션을 삭제하거나 운영 DB/사용자 파일을 지우지 않는다.
